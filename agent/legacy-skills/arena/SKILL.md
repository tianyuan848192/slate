# 霓虹擂台

适合"几个产品（模型、手机、芯片、云服务……）比一比"的片子：把每个对象当成一位**选手**，用一场比赛的节奏讲清楚谁强在哪里。

## 叙事结构（建议）

| 段落 | 用什么组件 | 要点 |
|---|---|---|
| 1. 开场 | `heading`/`title` + `player`（选手卡依次亮相） | 3 秒内抛出问题，比如"五个大模型，谁才是六边形战士？" |
| 2. 规则 | `panel` + `label`/`chip` | 说明比什么、数据从哪来、截至什么时间。这一段建立可信度，不要省 |
| 3. 分项比拼 | `barRace`（一个画面里切换 2～3 个评测项目） | 每个项目一句话解读，不要只念数字 |
| 4. 能力画像 | `radar`（先看全貌，再两两高亮对比） | 同一时间最多高亮 2～3 位选手 |
| 5. 领域总览 | `heatmap`（选手 × 领域），`best()` 标出各领域冠军 | 把"不同领域各有所长"讲出来 |
| 6. 焦点对决 | `versus` + `counter` | 挑最有看点的一组对比，或一个关键数字 |
| 7. 收尾 | `podium` 或总结卡 + 选择建议 | 给出"什么场景选谁"的结论，避免只说"谁第一" |

## 数据可信度（硬规则）

1. **只用有出处的数字**。优先级：
   - 官方技术报告、模型卡和官方博客；
   - 公开的第三方评测榜单（写明榜单名称和版本）；
   - 可信媒体转引的评测。
   - 用户上传的数据优先于联网数据。
2. **每个数据画面都要用 `NA.source` 标出处**，写明来源名称和数据日期（例如"来源：××官方技术报告 · 2026-09"）。所有来源都要写进 `sources.json`。
3. **查不到就写"未公布"**：`barRace` 和 `heatmap` 的数值填 `null`，`radar` 的维度换成数据齐全的那些。绝不编数字、绝不凭印象估算。
4. **不同口径不混排**：
   - 同一张图只放同一个评测、同一种设置（例如都是 pass@1）的分数；
   - 分数尺度不同就分开画，或者在标题里写明"归一化到 0～100"并说明方法；
   - 综合分、领奖台这类自己算出来的结论，要在画面上注明"按本片选取的 N 项评测等权平均"。
5. **说清局限**：旁白里提一句"评测分数不等于实际体验""版本更新后结果可能变化"。版本号写准确，不确定时用"截至某月公开的版本"。
6. 示例里的"模型 A～E"和数字都是占位符。正式做片时必须替换，`NA.watermark` 的"示例数据"角标也要去掉。

## 画面

- **舞台**：每镜先创建 `NA.stage()`。
  - 内容放 `st.world`（跟随镜头缓慢推近）；出处、角标放 `st.hud`（固定在屏幕上）。
  - 需要安静背景的数据镜头（排名赛、热力图）用 `floor: false` 关掉透视网格。
- **配色**：
  - 选手颜色固定用 `NA.C.series[i]`。同一位选手整片都用同一个颜色，按出场顺序分配，**不按名次分配**。
  - 数值、标签一律用文字色（`ink`、`ink2`、`muted`），颜色只放在条、点、边框上。
  - 两位以上的选手同屏时，要有图例（`NA.legend`）或直接标名字。
- **字体和尺寸**：
  - 标题用 `NA.heading`，它会自动放进安全区；
  - 正文不小于 2.6u，数字标签不小于 2.8u；
  - 一屏只突出一个结论。
- **构图**：
  - 数据画面用 `NA.panel` 框起来（玻璃面板 + 四角括号 + 扫描线），面板放在标题下沿（`heading().bottom`）和字幕区（`SLATE.captionZone.y`）之间；
  - 镜头会推近约 3.5%，内容离安全区边缘要留一点余量。

## 动画和节奏

- **开场**：舞台自带故障风入场（`enter: 'glitch'`），标题用 `title.draw` 逐字升起，接着用 `sweep` 扫一道光。
- **数据**：
  - 柱子和多边形都是"长出来"的，数字跟着滚动；
  - 排名赛每个项目至少停留 2.5 秒再切换（`timeline` 里的时间点间隔不少于 2.5 秒）。
- **高亮**：`player.focus`、`radar.focus`、`heatmap.best` 要跟旁白点名的时刻对齐（看 `SLATE.captions`）。
- **节奏**：每镜 6～10 秒。全片 60 秒大约 7～9 镜，数据镜头和"人话解读"的镜头交替出现。
- **结尾**：最后一镜可以用 `exit: 'flash'` 收尾。

## 用法

```html
<link rel="stylesheet" href="/skills/arena/style.css">
<script src="/skills/arena/components.js"></script>
<script>
  const { seg, u: U, width: W, height: H, safe } = SLATE;
  const st = NA.stage({ floor: false });
  const h = NA.heading(st.world, { text: '代码能力谁最强？' });
  const y0 = h.bottom + U * 3, y1 = SLATE.captionZone.y - U * 3;
  const race = NA.barRace(st.world, { x: safe.x + U * 6, y: y0, w: safe.w - U * 12, h: y1 - y0, items, frames, digits: 1 });
  const src = NA.source(st.hud, { text: '来源：…… · 2026-09' });
  function render(t) { st.set(t); h.draw(seg(t, 0.1, 0.9)); race.set(t, [[0.8, 0], [4, 1]]); src.draw(seg(t, 1, 1.5)); }
</script>
```

- 组件的参数写在 `components.js` 每个函数前的注释里。
- 完整示例（都可以复制后修改）：
  - `example/index.html`：开场和选手卡；
  - `example/race.html`：排名赛；
  - `example/radar.html`：雷达对比；
  - `example/heatmap.html`：领域热力图；
  - `example/finale.html`：对决、大数字和领奖台。
- **不要用 `top`、`name`、`parent` 当全局变量名**，它们和浏览器自带的全局变量冲突，脚本会报错。
