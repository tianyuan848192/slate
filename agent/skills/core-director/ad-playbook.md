# 广告片打法

宣传类写法（产品介绍、新品发布、功能上新、品牌故事、促销活动）通用的打法：结构、开场钩子、节奏、文案和落版。每种写法自己的结构和要点在 `genres/<id>.md`，和本文件冲突时以写法文件为准。流程、场景代码、字幕区和自检仍以 SKILL.md 为准，动效见 `motion-rules.md`。风格 Skill（比如 film-swiss-motion、film-living-screencast、film-dark-keynote）里写明的规则优先于本文件。

## 1. 先定一句承诺

动笔之前，先写清楚这六项：

| 要素 | 问自己 |
|---|---|
| 受众 | 谁会看到？会在哪里刷到？ |
| 痛点或欲望 | 他们已经想解决什么、想得到什么？ |
| 承诺 | 全片的一句话：用了它，你会怎样（写进 brief 的 summary） |
| 产品的角色 | 在这个故事里，产品做了什么？ |
| 证明 | 演示、参数、数据、用户评价、合作方。只用用户给的或有出处的 |
| 行动 | 看完要做的那一件事 |

- 片子围绕承诺展开，不是一张功能清单。官网是按信息排版的，广告要按情绪的顺序走：素材里的内容可以打乱、合并、删掉。
- 价值先于证据：承诺最迟在第二镜说出来，后面的功能、演示、数据都是它的证据。
- 自检：删掉所有证据镜，剩下的镜头仍能说清"为什么要买"；删掉讲价值的镜头后，如果片子看上去还成立，那它只是一份功能巡览。

## 2. 选一条主线

| 主线 | 适用 | 镜头顺序 |
|---|---|---|
| 痛点→放大→解决 | 痛点明确又迫切（工作流程、效率问题） | 钩子 → 痛点 → 放大代价 → 产品登场 → 演示或证明 → 行动 |
| 前后对比 | 用新做法替换旧做法 | 以前 → 预告"现在" → 产品 → 第 1 步 → 第 2 步 → 惊喜结果 → 行动 |
| 演示循环 | 界面一看就懂，最好直接看它跑起来 | 一个问题 → 产品亮相 → 演示 1 → 演示 2 → 建立信任 → 行动 |
| 卖点-利益连环 | 功能很多，或者靠品位、身份打动人 | 品类钩子 → 卖点 → 利益 → 卖点 → 利益 → 高潮 → 行动 |
| 未来场景 | 卖一种新方式或新品类 | 设想 → 点出产品 → 痛点消失 → 原理 → 结果 → 行动 |

卖点多的时候，无论走哪条主线，都用"卖点→利益"的节奏：每个功能都翻译成观众得到的好处，不要把功能一个接一个堆上去。

## 3. 各类广告的骨架

下表是速查，详细写法见各写法文件（App 演示归在产品介绍里）。

| 类型 | 主线 | 骨架 | 关键镜头 |
|---|---|---|---|
| 新品发布 | 卖点-利益连环或未来场景 | 悬念或奇观钩子 → 英雄揭示（产品名加一句定位）→ 2～3 个卖点 → 证明（参数、数据）→ 价格和上市时间 → 落版 | 英雄揭示：遮罩揭开加轻推，是全片最隆重的一次 |
| 功能上新 | 前后对比或痛点→放大→解决 | 旧做法的麻烦 → "现在" → 新功能 2～3 步演示 → 结果（省了多少时间、少了几步）→ 行动（"更新到最新版"） | 前后对比：同一件事，左右或先后两种做法 |
| 品牌宣传 | 未来场景或卖点-利益连环 | 情境共鸣 → 价值主张 → 三个印证（场景、人群、数字）→ 口号落版 | 锚定轮换：品牌名不动，旁边的人群、场景轮换 |
| App 演示 | 演示循环 | 一个具体问题 → 打开 App 的第一眼 → 核心流程 2～4 步 → 结果 → 更多场景 → 下载 | 界面走查：用用户上传的截图做界面，一镜一个操作 |
| 促销活动 | 痛点→放大→解决的短版 | 福利钩子（价格、限时）→ 商品英雄 → 1～2 个卖点 → 价格揭示（原价划掉）→ 期限加行动 | 价格翻牌：数字逐位停住 |

- 界面演示通常是连续 3 镜以上的一段（输入 → 响应 → 结果 → 好处），用同一个界面贯穿，不要只给一镜。
- 产品界面优先用用户上传的截图。必须重画时，只画讲到的部分，照着截图的布局和配色画，不要添加产品没有的功能。
- 配乐：发布会、科技产品用 tech；消费品、促销用 bright；高端品牌用 calm 或不用配乐。
- 音色：发布会、科技产品用正式播报或真诚的亲切聊天类；消费品、种草用亲切聊天类；年轻、搞笑路线用搞笑吐槽类；儿童产品用萌趣卡通类。

## 4. 前 3 秒

| 时间 | 必须做到 |
|---|---|
| 第 0 帧 | 画面上已经有内容（底色加一个主体），不能是空白或纯色 |
| 0.1～0.3 秒 | 第一个动作开始 |
| 1.5 秒内 | 钩子的关键词已经念出来，并以大字或画面的形式出现 |
| 3 秒内 | 观众知道"这跟我有什么关系" |

- 不要用 Logo 片头、公司介绍、"大家好"、"今天给大家介绍"开场。品牌需要早点露面时，把小 Logo 常驻在角落。
- 钩子说观众能得到的结果（得到什么、免掉什么），不说功能名、型号或参数清单。数字只在代表利害时用（"省下 40% 的时间"），不用来罗列（"23 项升级"）。
- 打法：直击痛点（"每天加班改表格？"）、反常识（"最贵的不是会员，是你的时间"）、冲击数字、提问、场景代入（"你是不是也……"）、前后对比、产品奇观（直接给最好看的那个画面）、福利钩子（促销用）。不要每支都用数字开场。
- 第一镜旁白 12～25 字。钩子立住了，再点出产品名。
- 信息流里有人静音看，所以钩子在画面上也要成立：关键问题或数字要用大字出现，不能只靠字幕。

## 5. 节奏和密度

| 时长 | 镜头数 | 旁白总字数 | 推荐结构 |
|---|---|---|---|
| 15 秒 | 2～3 | 55～60 | 钩子（3～5 秒）→ 一个卖点或英雄揭示（6～7 秒）→ 落版加行动（4～5 秒） |
| 30 秒 | 3～5 | 115～125 | 钩子 → 产品亮相 → 1～2 个卖点 → 证明 → 落版 |
| 60 秒 | 5～8 | 240～250 | 完整主线：2～3 个卖点，一镜证明，一镜落版 |

- 字数按每秒 4.5 字、每镜约 0.8 秒没有旁白来估算。15 秒只讲一个卖点。把钩子、三个卖点和行动全塞进 15 秒，只会变成噪音。
- 镜长一般 5～10 秒，短广告的钩子镜可以短到 3～5 秒（风格 Skill 另有规定时按风格）。镜内每 1.5～3 秒一个新事件；元素落定后至少停 1 秒。
- 动手之前先给全片定一个节奏型，比如"快-快-慢-快-停"。最慢的镜头至少比最快的慢 3 倍。旁白里最重的那句话，就是能量的高峰。
- 安排一处"停"：一镜只有一句话，画面几乎不动，常放在英雄揭示或落版之前。
- 整屏冲击（满版色块扫屏、穿越式转场、大幅推镜）全片 2～3 处：英雄揭示一处，落版一处，最多再加一处；相邻两处至少隔 8 秒。
- 卖点之间的版式要有变化，全片至少用三种构图。同一种卖点结构（推近 → 结果 → 标注）可以重复三次形成节奏，但每次的画面主体要不同。

## 6. 文案：旁白和屏上字

**旁白**
- 每镜 15～40 字，一句不超过 20 字。逗号之间不超过 16 字（竖屏 12 字），正好是一行字幕。
- 多说"你"，多用动词开头，说具体的事："一句话，出一支视频"胜过"智能高效的视频创作解决方案"。
- 把功能翻译成利益：

| 功能说法 | 利益说法 |
|---|---|
| 支持 65W 快充 | 充 10 分钟，用一下午 |
| 内置 200 套模板 | 一打开就有现成的版式 |
| AI 自动剪辑 | 素材扔进去，成片自己出来 |

- 三个卖点用排比，节奏是短、短、长，最后一个分量最重。
- 品牌名至少说两次：亮相时一次，落版时一次。
- 不说空话，比如"赋能""一站式""颠覆""重新定义""极致体验""开启新篇章""无缝衔接"。
- 不用极限用语：最、第一、唯一、顶级、首个、国家级、100%，除非用户给了可以核实的出处。性能数字要写明测试条件，用小字注脚放在画面角落，不要放进字幕区。
- 优惠和承诺（"7 天无理由""限时"）只写用户给了的，不要自己编。
- 想要更有劲，可以选 happy、surprised 这类情绪，或者活泼的音色。搞笑吐槽类音色配一两处语气词效果最好。

**屏上字**
- 屏上字和旁白不是一回事。字幕会显示整句，屏上只放卖点词、数字、价格和口号。
- 一行不超过 8 个汉字，最多两行。数字用阿拉伯数字，单位的字号小一档。
- 在旁白念到时出现（对齐 `SLATE.captions`），连续可见的时间不少于"汉字数 ÷ 4.5 + 其他字符数 ÷ 15 + 1.5 秒"。
- 价格：到手价字最大，原价划掉放在旁边，"¥"和小数部分小一档。

## 7. 产品和界面的镜头类型

| 镜头 | 画面和动作 | 用在 | 要点 |
|---|---|---|---|
| 英雄揭示 | 遮罩或光带揭开产品，轻推 1.00→1.05 | 产品亮相 | 全片最隆重的一次；产品高度占画面 40%～50% |
| 局部推近 | 画面落定 0.5～1.5 秒后，用 1～2 秒把局部推近到 1.5～3 倍 | 一个关键部件或参数 | 推近后至少停 1.5 秒；推之前确认文字推完后仍在安全区内 |
| 卖点标注 | 从产品上的一点画出引线，末端出标签 | 一个画面讲 2～3 个卖点 | 一条引线对应一个旁白分句；标签不超过 6 个字 |
| 参数翻牌 | 数字滚动，或逐位翻到目标值 | 续航、速度、价格 | 滚动 1.2～2.5 秒，念到时停住，之后至少停 0.5 秒 |
| 卖点网格 | 3～6 张卡片错峰拼成网格 | 一次展示功能的广度 | 错峰总时长不超过 0.5 秒，或者一张卡对应一个分句；卡片大小要分主次 |
| 前后对比 | 左右两栏（竖屏改上下），先旧后新 | 功能上新、效果对比 | 只比两个；旧的变灰或划掉，新的用强调色 |
| 界面走查 | 一个窗口或手机框常驻，屏幕内容按流程切换 | App 演示 | 每个界面状态停 1.5～3 秒；一镜一个操作 |
| 光标操作 | 光标移到按钮上按下，出现涟漪，界面随之响应 | 演示一个具体操作 | 点击前 0.3～0.5 秒开始推近到 1.4～2.2 倍；同一时刻只有一个主角在动 |
| 输入→生成 | 输入框里打字，出现等待状态，然后结果出现 | AI、搜索类产品 | 打字每秒 7～10 字；等待 0.5～1 秒；结果分块出现 |
| 锚定轮换 | 品牌名或主句不动，旁边的人群、场景、用法轮流替换 | 品牌宣传、"适合所有人" | 锚点入场后不再移动；每项至少停 0.8 秒 |
| 撞开选项 | "是 A？是 B？"轮换几次，然后主角撞进来把字推开 | 钩子、定义品类 | 撞入是一次碰撞，不是淡入 |
| 社会证明 | 用户数、评分滚动；合作方 Logo 墙 | 证明 | 只用用户给的数字和 Logo；最大的数字最后出 |
| 价格揭示 | 原价出现 → 划掉 → 到手价翻牌落定 | 促销 | 到手价是这一镜最大的字 |
| Logo 落版 | 清场 → 标志画出或弹出 → 字标随后出现 → 口号和行动 | 最后一镜 | 见第 8 节 |

## 8. 落版和行动号召

- **只要一个行动**，写成"动词 + 对象 + 去哪里"：立即下载、搜索「品牌名」、扫码领取、点击下方链接、现在预约。不要并列两三个行动。
- 落版元素不超过 4 个：Logo、一句口号、行动（网址、搜索词或二维码，只用用户给的），以及可选的价格或日期。
- **先搭好再停住**：落版在最后一镜的前 40% 内搭完，之后完全静止到结尾，最多保留一个很小的提示动作（比如箭头每两拍向前点一下）。旁白在静止期间念出行动号召。完整的落版画面至少可见 2～2.5 秒。
- Logo 用用户上传的原图，不改形状和比例。先出标志，落定后约 0.2 秒再出字标。
- 二维码要足够大（建议不小于画面短边的 20%），四周留白，不要压在字幕区和竖屏的平台按钮区。
- 最后一镜旁白 15～25 字，结构是"品牌名 + 一句承诺 + 一个行动"，例如"轻记，想到就记下。去应用商店搜轻记。"
- 落版不要一闪而过，也不要在落版上加新的卖点。

## 9. 画幅和平台

| 画幅 | 常见去处 | 构图 |
|---|---|---|
| 16:9 | 官网、B 站、发布会大屏、门店横屏 | 可以左右分栏（图占 60%，字占 40%）；字幕区在底部约 16% 的位置 |
| 9:16 | 抖音、快手、视频号、小红书的竖屏信息流 | 上下堆叠；内容放在高度 7.5%～67% 之间（顶部留给平台栏，70% 往下是字幕和平台按钮）；右侧中下部是点赞、评论按钮，重要内容离右边缘留出约 12%；视觉中心在高度 37%～40% 左右 |
| 1:1 | 朋友圈、微博信息流、电商主图视频 | 只有两个小元素时可以左右并排，其余上下堆叠；可用的中心区域小，字要更少 |
| 4:5 | 想在信息流里多占一点高度 | 按 1:1 的思路，纵向多放一行 |

- 从写分镜开始就按选定的画幅设计，不要先做横屏再裁。字号按短边算；竖屏一行的字更少，不超过 8 个。
- 竖屏广告节奏更快：15 秒 2～3 镜，每镜一件事，第一镜就给出产品或结果，不要铺垫。
- 字幕区和竖屏的平台区，以运行时给的 `SLATE.captionZone` 和风格 Skill 的版心为准。

## 10. 常见问题和改法

| 症状 | 改法 |
|---|---|
| Logo 或公司介绍开场，3 秒里没有信息 | 第一镜换成钩子；Logo 放在角落，或者留到落版 |
| 一串功能名，看完记不住 | 只留 1～3 个卖点，每个都翻译成利益 |
| 每个卖点都是同一个版式 | 换用第 7 节里的其他镜头类型，全片至少三种构图 |
| 15 秒塞了三个卖点 | 改成钩子 + 一个卖点 + 行动 |
| 说得很满，没有证据 | 每个承诺都配一段演示，或一个有出处的数字 |
| 行动号召含糊，或者有好几个 | 只留一个，写成"动词 + 对象 + 去哪里" |
| 落版一闪就结束 | 落版在最后一镜的前 40% 搭完，然后静止停住 |
| 屏上字和字幕重复 | 屏上只放关键词、数字、价格 |
| 竖屏直接套用了横屏版式 | 改成上下堆叠，避开顶部和右侧的按钮区 |
| 弹跳、闪烁、到处在动，显得廉价 | 按 `motion-rules.md`：以顺滑减速为主，一次只动一个主角 |
| 用了极限用语，或编了优惠 | 删掉；只写用户给的、能核实的内容 |
| 重画的界面不像这个产品 | 用用户的截图；必须重画时照着截图的布局和配色 |
| 从头到尾一样快 | 先定节奏型，安排一处"停"，高潮之前放慢 |
