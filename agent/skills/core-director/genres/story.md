# 写法：故事案例

**适合**：讲一个真实的案例、事件或一段历史，比如企业的兴衰、一次事故的复盘、一个科学发现、一个人的经历。

**和其他讲解写法的区别**：靠故事的张力带人看完，道理放在最后。主线是时间和因果。

先读 `explainer-playbook.md`（讲解类通用的讲法、旁白和画面规则），本文件只写故事特有的部分，两者冲突时以本文件为准。写法只管剧本怎么组织；配色、字体、版式和动作由风格决定。

## 1. 先想清楚

| 要素 | 问自己 |
|---|---|
| 主角 | 一个人、一家公司还是一个团队？ |
| 想要什么 | 主角的目标 |
| 冲突 | 挡在路上的是什么 |
| 转折 | 关键的决定、发现或意外 |
| 结局 | 最后怎样了 |
| 道理 | 一句能用到别处的话，写进 brief 的 summary |

## 2. 结构

悬念开场（先给结局或最戏剧性的那一瞬间）→ 背景（主角是谁、想要什么）→ 冲突升级（2～3 镜）→ 转折 → 结局 → 道理，并回扣开场。

- 悬念开场的写法：用一个具体的时间和动作，把结果先露出一角，比如"那一年，他们做出了第一台样机。然后，把它锁进了柜子。"
- 转折之前放一个喘息镜：一句话，画面几乎不动。
- 道理只说一次，不说教。

## 3. 真实性

- 案例必须真实、有出处。时间、数字、人名都要核实，写进 sources.json。
- 不确定的细节不编，也不给真实人物编台词；要用原话，必须有出处。
- 用户给的内部案例，只用用户给的内容。

## 4. 按时长

| 时长 | 怎么讲 |
|---|---|
| 15 秒 | 讲不了完整的故事，只讲一个瞬间加一句道理 |
| 30 秒 | 悬念开场 → 转折 → 道理 |
| 60 秒 | 完整结构 |
| 3 分钟以上 | 分三幕，或者两三条线交替讲 |

## 5. 旁白和配音

- 讲故事的语气：具体的时间、地点、人物和动作，多用动词。
- 越接近转折，句子越短，制造紧张感。
- 音色：故事电台类。配乐 calm。

## 6. 画面

- 用时间线贯穿全片，节点按真实间隔排列。
- 人物和场景可以用风格化的插画表现，不必写实。
- 关键时刻用局部放大或者定格。

## 7. 常用镜头

时间线、悬念问题卡、前后对比的双栏、表现代价的大数字、喘息卡、总结卡。

## 8. 风格

用户选了风格就用用户的，结构照样按本文件写。用户没选时，默认用 `film-halftone-dossier`（复古档案感）。也可以从下面挑：
- 温情的故事：`film-watercolor`、`film-urban-sketch`；
- 古代和传统题材：`film-ink-wash`、`film-shadow-puppet`；
- 年代感：`film-silent-film`、`film-engraving`。

## 9. 常见问题

| 症状 | 改法 |
|---|---|
| 像流水账 | 找出冲突和转折，删掉和它们无关的经过 |
| 道理太多 | 只留一个，放在最后 |
| 编了细节 | 删掉，或者换成有出处的事实 |
| 开场平淡 | 把结局或最戏剧性的瞬间提到第一镜 |
