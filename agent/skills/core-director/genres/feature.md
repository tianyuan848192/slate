# 写法：功能上新

**适合**：告诉已有用户一个新功能或一次改版，比如更新说明视频、应用内公告、社交媒体上的更新预告。

**和产品介绍的区别**：观众已经认识这个产品，不用再介绍它是什么。核心是"以前怎样，现在怎样"。

先读 `ad-playbook.md`（宣传类通用的结构、文案和落版规则），本文件只写功能上新特有的部分，两者冲突时以本文件为准。写法只管剧本怎么组织；配色、字体、版式和动作由风格决定。

## 1. 先想清楚

- **旧的麻烦**：用户每天都在忍的那件事，越具体越好。
- **新功能**：叫什么，在哪里找到。名称照用户的资料原样写。
- **结果**：省了多少时间、少了几步。用户给了数字就用数字。
- **行动**：一个，比如"更新到最新版"，或者"在设置里打开"。

## 2. 结构

旧做法的麻烦（最好用真实界面）→ "现在" → 新功能 2～3 步演示 → 结果 → 行动。

- 关键镜头是**前后对比**：同一件事的两种做法，左右并排（竖屏改成上下）或者先后出现，旧的变灰。
- 演示用用户上传的截图，不编界面。

## 3. 按时长

| 时长 | 怎么讲 |
|---|---|
| 15 秒 | 一组前后对比，加行动 |
| 30 秒 | 完整结构 |
| 60 秒 | 可以讲两个相关的新功能，每个都有前后对比 |

## 4. 旁白和配音

- 直接、轻快，"以前……现在……"。
- 不要从头介绍产品，也不要讲公司。
- 音色：亲切聊天类。配乐 bright 或 tech。

## 5. 常用镜头

前后对比、界面走查、光标操作、参数翻牌（省下的时间或步数）、Logo 落版（见 `ad-playbook.md` 第 7 节）。

## 6. 风格

用户选了风格就用用户的，结构照样按本文件写。用户没选时，默认用 `film-living-screencast`。也可以从下面挑：
- 排版感强的公告：`film-swiss-motion`；
- 图标化、轻快：`film-pictogram-motion`。

## 7. 常见问题

| 症状 | 改法 |
|---|---|
| 又从头介绍了一遍产品 | 删掉，直接从旧的麻烦开始 |
| 没有前后对比 | 加一镜：同一件事，以前怎么做，现在怎么做 |
| 功能名称和界面对不上 | 照用户的截图和资料改 |
| 看完不知道在哪里找到 | 落版写清"在哪里打开" |
