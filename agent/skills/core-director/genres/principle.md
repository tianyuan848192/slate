# 写法：原理讲解

**适合**：讲清一个概念、机制或技术是怎么运作的，比如 RAG、复利、HTTPS、发动机。观众想真的弄懂，常常是工作或学习要用。

**和知识科普的区别**：要讲到机制，看完能用自己的话复述"它为什么能做到"。必要的术语可以用，但每个都要解释。

先读 `explainer-playbook.md`（讲解类通用的讲法、旁白和画面规则），本文件只写原理讲解特有的部分，两者冲突时以本文件为准。写法只管剧本怎么组织；配色、字体、版式和动作由风格决定。

## 1. 先想清楚

- 先回答 `explainer-playbook.md` 第 1 节的六个问题，尤其是"论点"：看完只记住的那一句话。
- 机制要能画成**一个舞台上的连续变化**：输入是什么，中间经过几步，每一步改变了什么，输出是什么。画不出来，说明还没想清楚机制。
- 找一个贯穿全片的类比或一张"主图"。主图在主体部分一镜一镜长大，开场和结尾都回到它。

## 2. 结构

用"概念讲解"结构：困惑或问题开场 → 一句话论点 → 先给框架（"整个过程分三步"）→ 一层层揭开机制（3～5 镜，同一个舞台）→ 一个带真实数字的算例，或者一个"什么情况下它会失效"的反例 → 回扣主图，再说一遍论点。

- 机制部分有明确先后顺序时，按流程一步一镜讲，页眉标"2 / 4"。
- 要讲两个方案的区别时，主体改成对比双栏，按同一维度逐行对照。

## 3. 按时长

| 时长 | 怎么讲 |
|---|---|
| 15 秒 | 它解决什么问题，加上最核心的一步 |
| 30 秒 | 一个机制讲透 |
| 60 秒 | 3～4 步机制，加一个算例 |
| 3 分钟以上 | 开头给路线图，分 2～3 段，每段一个子机制，段尾一句小结 |

## 4. 旁白和配音

- 冷静、清楚，多用路标词："第一步……接着……问题在于……这就是为什么……"
- 术语第一次出现时，紧跟一句大白话；之后全片用同一个叫法。
- 音色：正式播报类，或者真诚的亲切聊天类。配乐 calm、tech，或不用。

## 5. 常用镜头

结构拆解、流程图、因果链、公式拆解、类比对照、局部放大、对比双栏（见 `explainer-playbook.md` 第 9 节）。

## 6. 风格

用户选了风格就用用户的，结构照样按本文件写。用户没选时，默认用 `film-iso-infographic`。也可以从下面挑：
- 硬核机械和工程原理：`anatomy`（写起来慢，一台机器贯穿全片）；
- 工程图：`film-blueprint`；
- 边讲边推导：`film-whiteboard`。

## 7. 常见问题

| 症状 | 改法 |
|---|---|
| 只有名词，没有机制 | 画出"变化"：每一步之前什么样、之后什么样 |
| 主体只有一镜 | 拆成 3～5 镜，在同一个舞台上连续推进 |
| 类比比概念还难懂 | 换成受众日常里的事物，说清两三处对应关系和边界 |
| 看完说不出论点 | 论点最迟第二镜说出来，最后一镜再说一遍 |
