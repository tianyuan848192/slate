# 写法：教程步骤

**适合**：教一件能照着做的事，比如软件设置、操作流程、制作方法、办事流程。

**和原理讲解的区别**：观众看完要能**做**，不只是懂。顺序和可操作性压倒一切，每一步都要具体到动作。

先读 `explainer-playbook.md`（讲解类通用的讲法、旁白和画面规则），本文件只写教程特有的部分，两者冲突时以本文件为准。写法只管剧本怎么组织；配色、字体、版式和动作由风格决定。

## 1. 先想清楚

| 要素 | 问自己 |
|---|---|
| 结果 | 做完是什么样？省掉了什么麻烦？ |
| 准备 | 开始前需要什么：工具、材料、账号、权限 |
| 步骤 | 3～6 步。超过 6 步就分组，比如"准备、操作、检查"三段 |
| 易错点 | 每一步最容易错在哪里 |

步骤和名称以用户的资料为准：界面上的按钮名、菜单名、表单名照原样写，不要自己编。

## 2. 结构

先给结果（做完的样子，或者能省下的麻烦）→ 准备（一镜说清需要什么）→ 步骤 1 到 N（一镜一步，同一个舞台，页眉标"步骤 2 / 4"）→ 检查（怎么确认做对了）→ 收尾（一个常见错误的提醒，或者下一步可以做什么）。

## 3. 每一步怎么写

- 旁白用动词开头的祈使句："打开设置""点右上角的加号""把面粉倒进碗里"。一句只讲一个动作。
- 有易错点时，加一句"注意"，只说一个。
- 画面里，当前这一步高亮，已完成的步骤打勾、变淡。
- 操作要看得清：软件界面用用户的截图，推近到操作的位置，用光标点击和涟漪表示操作（见 `ad-playbook.md` 第 7 节的界面走查、光标操作）。
- 每一步做完停 1 秒左右，让观众看清结果再进入下一步。

## 4. 按时长

| 时长 | 怎么讲 |
|---|---|
| 15 秒 | 只适合一两步的小技巧 |
| 30 秒 | 3 步 |
| 60 秒 | 4～6 步 |
| 3 分钟以上 | 分成两三段，每段开头说清这一段要完成什么 |

## 5. 旁白和配音

- 语速平稳，清楚，不赶。
- 音色：亲切聊天类。配乐 calm 或不用，音乐不要盖过操作的节奏。

## 6. 常用镜头

编号清单、流程图、界面走查、光标操作，以及"错误做法和正确做法"的对比双栏。

## 7. 风格

用户选了风格就用用户的，结构照样按本文件写。用户没选时，默认用 `film-whiteboard`。也可以从下面挑：
- 软件操作：`film-living-screencast`；
- 装配和工程步骤：`film-blueprint`。

## 8. 常见问题

| 症状 | 改法 |
|---|---|
| 跳了步骤 | 按真实操作重新走一遍，补上省略的那一步 |
| 一镜里有两个动作 | 拆成两镜 |
| 名称和界面对不上 | 照用户的截图和资料改 |
| 不知道做对了没有 | 加一镜"检查"：做对了应该看到什么 |
