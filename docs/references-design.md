# 资料：参考资料和联网搜索（取代讲解稿）

2026-10-15 定稿。

## 1. 用户看到的

新建页最上面的描述块合成一个整体：

```
┌ 描述 ─────────────────────────────────────────┐
│ 用一段话说清楚想做什么……                         │
├──────────────────────────────────────────────┤
│ 联网搜索 [开]   强制引用 [关]   ＋ 参考资料（上传 / 粘贴文字 / 链接） │
│ · 产品白皮书.pdf  320 KB  备注：重点看第三节       ✕ │
│ · 术语表（粘贴的文字） 1,200 字                  ✕ │
│ · https://blog.example.com/…  博客             ✕ │
└──────────────────────────────────────────────┘
```

- 快速模式和高级模式都有这一块。
- 高级模式里的**讲解稿**（大纲、上传讲解稿、逐字讲解）去掉。
- **素材**：起初只保留图片、Logo 和风格参考网站，当天又整块下线。当内容参考的网站改成参考资料里的链接。
- 顶部原来那个独立的联网搜索开关挪进这一块。

| 资料 | 形式 | 限制 |
|---|---|---|
| 内部资料：文件 | pdf、docx、md、txt、csv、xlsx | 每个不超过 1 MB |
| 内部资料：粘贴文字 | 一段文字，可以起个标题 | 每段不超过 2 万字 |
| 外部资料：链接 | 博客、在线文档。开工前由服务器抓取正文 | 最多 5 个 |
| 外部资料：联网搜索 | 开关，默认开 | Agent 最多搜 6 次 |

- 文件、文字和链接合计最多 10 份，每份可以加一句备注。
- 所有资料抽出的文字合计约 20 万字，超过时提示用户精简。

**强制引用**（默认关）：

| | 关：参考 | 开：强制 |
|---|---|---|
| 怎么用资料 | 当背景和灵感，可以发挥，可以补充 Agent 自己的知识和搜索结果 | 片子里的事实、数字和专业术语只能来自资料（内部资料、链接、联网搜到并列进来源的）；资料里没有的就不讲。叙事角度可以有创意 |
| 资料摘要 | 每份都要交代用了什么、没用的说明原因 | 同左 |
| 剧本核对 | 只拦和资料矛盾的说法 | 和资料矛盾的、找不到依据的、术语用错的，都要改 |

## 2. 执行顺序

步骤顺序改成：**资料整理** → 需求分析 → 写剧本 → 分镜 → 写代码 → 渲染 → 合成。

1. **开工前**（turn Lambda，在会话里执行确定性的命令，不经过模型）：
   - 抓取链接；
   - 在会话里运行 `slate-refs build`：把每份资料抽成纯文本 `input/refs/<编号>.md`，并生成目录 `input/refs/index.json`（编号、标题、类型、备注、来源、字数、章节标题和行号）；
   - 目录同时存进任务记录，前端可以直接显示。
2. **资料整理**（research）：
   - Agent 先读目录，再读资料：一份不超过 3 万字的读全文，更长的先读章节目录、再读相关章节；
   - 联网搜索开着时按需搜索；
   - 写 `notes.json`（资料摘要）并用 `slate-publish notes` 发布。服务端检查目录里的每份资料都交代了，缺一份就拒绝发布；
   - 联网和链接的来源照旧写进 `sources.json`。
   - 没有任何资料、联网也关了的时候，这一步跳过。
3. **需求分析**：结合资料摘要和描述，定写法、受众、论点，写 `brief.json`。
4. **写剧本**：按资料摘要和需求写 `script.json`。`slate-publish script` 发布前会自动核对：
   - 由 Slate-llm（Sonnet 5.5）比对剧本和资料，按强制引用的开关决定拦哪些问题；
   - 有要拦的问题就发布失败，返回问题清单，Agent 改完再发；
   - 最多两轮。第三次发布照常通过，没解决的问题记进核对结果给用户看；
   - 核对按看图计费。
5. 之后的步骤照常。
   - 长片：主会话按资料写讲稿和总纲；各章会话读 `notes.json` 里的术语，画面上出现专业词时也用对。

## 3. 接口（前后端按这个对接）

- `POST /api/uploads`：加一个字段 `purpose`，取值 `"ref"` 或 `"asset"`，默认是 `asset`。
  - `ref` 只接受 pdf、docx、md、txt、csv、xlsx，大小不超过 1 MB；
  - 不符合时返回 400，`message` 是中文说明。
- `POST /api/tasks`：两种模式都可以带 `refs`：
  ```json
  {"refs": {"web": true, "strict": false, "items": [
     {"kind": "file", "uploadId": "…", "name": "白皮书.pdf", "note": "重点看第三节"},
     {"kind": "text", "title": "术语表", "text": "……", "note": ""},
     {"kind": "link", "url": "https://…", "note": "博客"}]}}
  ```
  - 顶层的 `web_search` 还接受（老前端），以 `refs.web` 为准。
  - `options.script` 不再使用（老前端传了也忽略）。
  - `options.assets`（素材）已下线，传了也忽略；内容参考的网站要放进 `refs.items`，用 link 类型。
- `GET /api/tasks/{id}`：
  - `request.refs`：`{web, strict, items: [{id, kind, name|title|url, note, chars, error}]}`。`chars` 是抽出的字数；链接抓取失败时有 `error`。
  - `notes`：资料摘要，格式是 `{angle, items: [{id, summary, used, facts: [..], terms: [{term, meaning}], reason}]}`。没有资料时为 null。
  - `scriptCheck`：剧本核对结果，格式是 `{rounds, ok, strict, issues: [{kind: "contradiction"|"unsupported"|"term", text, ref, suggestion}]}`。
  - `steps` 的顺序变成 research（资料整理）在前，analyze（需求分析）在后。
- 老任务：`request.options.script` 里还有讲解稿的，生成页的"你的设置"照常显示"讲解稿"；修改时 Agent 照旧使用。
