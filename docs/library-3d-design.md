# 生成 3D 图片 + 素材库：设计

2026-10-16 定稿，依据开发期间的 img2threejs 实测。

## 一、生成 3D 图片（新的任务类型）

### 用户看到的

- 新建页顶部加一个切换：**视频** / **3D 图片**。
- 3D 图片的输入：
  - 一段描述，必填，比如"薄荷绿双铃闹钟，复古金属质感"；
  - 0～4 张同一物体不同角度的照片，可选。png、jpg、webp，每张不超过 10 MB。
  - 角度越全越像。只有一张图时，看不到的面靠推测；没有图时，Agent 先按描述画一张示意图再建模。
- 生成页的步骤：看图分析 → 建模规格 → 建模 → 比对修正 → 导出。
- 成品页：
  - 可以拖动旋转的 3D 预览、多角度图片（2026-10-16 起不再出转台视频：3D 图片只出图片和文件，拖动预览就能全角度看）；
  - 下载 GLB 和 PNG；
  - 名称和标签可以改；
  - 可以像视频一样用对话修改，比如"提手改成棕色皮革"，每次修改出一个新版本。
- 做完自动进素材库。

### 怎么做

- **新的手册 `core-model3d`**：参考 img2threejs 的方法写我们自己的版本，**不用它的代码生成器和整套检查**。
  1. 分层看图，多张图一起看。没有图时先画示意图。
  2. 写建模规格：部件层级、比例、材质，以及哪些零件可以单独动。
  3. **手写** three.js 工厂函数：纯 JS，只依赖 three，零件放进 `userData.sculptRuntime.nodes`，和实测产出的格式一致。
  4. 渲染多角度，和参考图并排比对，最多 8 轮。达到"放进视频能一眼认出"就收尾。
  5. 导出：多角度图、GLB、3D 打印数据、素材卡（名称、标签、零件、推荐拍法、局限）。
- **新命令 `slate-model`**：`view`（多角度图和对比图）、`sketch`（示意图转 PNG）、`export`（导出新版本）。
  - 交给现有的 GPU 渲染机，新增这三种操作；渲染机调不通时退回 AgentCore Browser。
  - 实测里每次截图约 30 秒，换到 GPU 上会快不少。
- **修 `slate-look`**：输出上限从 1500 提到 8000。不改的话，复杂问题会返回空。这个问题做片自检时也会碰到。
- **计费**：和视频一样，按模型、看图、渲染记 Credit。实测一个模型约 7～10 美元，也就是 9～13 Credit，用时 40～65 分钟。
  - 新手册不走生成器那套绕路，预计会便宜一些，上线后实测再看。

## 二、素材库

### 放什么（每个用户自己的）

| 类别 | 怎么进来 | 能做什么 |
|---|---|---|
| 视频 | 每个任务的成片自动入库，带全部版本 | 预览、下载、改名和标签、删除。只用来保存历史视频，做新视频时不引用 |
| 3D 图片 | 每个 3D 任务的成品自动入库 | 预览（可旋转）、下载 GLB 和 PNG、改名和标签、删除、"用它做视频" |
| 文件 | 上传过的参考资料文件自动入库（pdf、docx、md、txt、csv、xlsx） | 预览文字、下载、删除；新建视频时直接选用，不用重新上传 |

- 这里说的"图片"指 3D 图片的成品。3D 任务上传的参考照片跟着它的 3D 素材一起保存，不单独列出来。普通照片仍然不单独作为视频素材，那个功能已经下线。
- 每个用户的容量上限默认 200 条、5 GB，管理端可以调。

### 在视频里引用

- 新建视频的描述块里有一个 **"＋添加资料"**（2026-10-17 起，原来的"＋参考资料"和"＋从素材库"合成一个入口），下拉里是上传文件、从素材库选、添加链接三项。"从素材库选"打开选择框，按类别分页、可以搜索。加进来的文件、链接、3D 图片都显示在同一个列表里。
  - **文件**：作为一份参考资料，和上传的一样走资料整理、强制引用这些逻辑。
  - **3D 图片**：作为"3D 素材"，系统做三件事：
    - 把模型文件放进任务的 `scenes/_shared/assets/<编号>/`；
    - 把素材卡（名称、标签、零件、推荐拍法、局限）写进任务说明；
    - Agent 读素材卡，自己决定哪几镜用、怎么拍：转台、推近、零件动画。
  - 做片手册加一节"3D 素材"，内容是实测里视频 Agent 的做法：加载模型、用零件表做动画、可以按风格调材质、不要另外重画。
- **不再把代码当文字资料传**。实测那支片贵了 5 倍，就是因为这个；改成文件之后就是正常价格。

### 存储

- 文件放在 `u/<用户>/lib/<编号>/` 下，记录存进任务表，键是 `LIB#<用户>`。视频和 3D 素材记录指向任务目录里的文件，不重复存储。
- 删除素材只删记录和素材库里的文件，不影响已经做好的视频。被引用过的模型，在那个任务里还有一份副本。

## 三、视频不被引用

素材库里的视频只用来保存自己的历史视频（用户 2026-10-16 确认），新建视频时"从素材库选"里只有 3D 图片和文件两类。

## 四、上线顺序

1. 修 `slate-look`，写 `core-model3d` 手册和 `slate-model` 命令，渲染机新增三种操作。
2. 3D 任务类型：后端校验、任务说明、步骤、成品和修改、计费、前端的新建和成品页。
3. 素材库：后端接口、存储，前端的素材库页和"＋从素材库"选择框，做片手册的"3D 素材"一节。
4. 端到端测试：一张图、四张图、纯文字各做一个 3D，再引用其中一个做视频，效果由你判断。

## 五、接口（前后端按这个对接）

### 上传
- `POST /api/uploads` 的 `purpose` 多一种取值 `"image"`：3D 任务的参考照片，只收 png、jpg、jpeg、webp，每张不超过 10 MB。`"ref"` 不变。

### 建任务 `POST /api/tasks`
- **3D 图片**：`{"product": "model3d", "description": "…", "images": ["u-…", …], "web_search": true}`
  - `images` 有 0～4 个上传编号，是同一物体不同角度的照片；`mode`、`refs`、`options` 都不用传。
  - `web_search`：联网搜索，默认开（2026-10-16 加）。描述或照片里有具体品牌、型号时，Agent 查它的尺寸、配色、材质和部件，最多 4 次，来源发布成 `sources`。搜索只拿得到文字，不能代替照片；和照片冲突时以照片为准。
- **视频**：原来的字段不变，新增两项：
  - `"models": ["<3D 任务号>", …]`：从素材库引用的 3D 图片，最多 3 个，必须是自己已经完成的 3D 任务；
  - `refs.items` 里可以有 `{"kind": "library", "fileId": "f-…", "note": ""}`：从素材库引用的文件，算参考资料的一份。

### 任务列表 `GET /api/tasks`
- 每项多一个 `product` 字段，取值 `"video"` 或 `"model3d"`。3D 任务有成品后还带 `thumbUrl`（35 度斜侧图的签名链接）。

### 任务详情 `GET /api/tasks/{id}`
- 多一个 `product` 字段。3D 任务的详情如下，`brief`、`script`、`storyboard`、`versions` 都是 null 或空：

  ```json
  {"product": "model3d",
   "steps": [{"name": "analyze", "label": "看图分析"}, {"name": "spec", "label": "建模规格"}, {"name": "model", "label": "建模"},
             {"name": "review", "label": "比对修正"}, {"name": "export", "label": "导出"}],
   "request": {"description": "…", "web_search": true, "images": [{"name": "front.jpg", "url": "<签名链接>"}]},
   "sources": {"queries": ["…"], "sources": [{"title": "…", "url": "…", "note": "…", "used": true}]},
   "model": {
     "asset": {"name": "…", "tags": ["…"], "summary": "…", "factory": "createXxxModel", "size": [0.3, 0.4, 0.2],
               "parts": [{"id": "handle", "name": "提手", "note": "…"}], "recommendedShots": ["…"], "limits": ["…"]},
     "versions": [{"n": 1, "views": [{"angle": 0, "url": "…"}, {"angle": 35, "url": "…"}],
                   "comparison": "<对比图，没有参考照片时为 null>", "glb": "<下载链接>", "at": 1792000000000}]}}
  ```
  - 每个字段的含义：`views` 是 0、90、180、270、35 度五张图；`asset` 在 Agent 发布素材卡之前是 null；用对话修改后多一个版本。
- `GET /api/tasks/{id}/module?v=<版本号>`：返回 `{"code": "<模型的 JS 源码>", "factory": "createXxxModel"}`，给前端的 3D 预览用。
  - 用法：前端把 `code` 转成 Blob，用 `import()` 动态导入。模型代码只 `import … from 'three'`，按页面的导入映射解析。

### 素材库
- `GET /api/library?kind=video|model3d|file&q=<搜索词>`：返回 `{"items": [...]}`，按更新时间倒序。三类条目的格式：
  - `video`：`{"id": "<任务号>", "kind": "video", "name", "tags", "createdAt", "updatedAt", "thumb": "<风格 id>", "versions": [{"n", "url", "download", "dur"}]}`
  - `model3d`：`{"id": "<任务号>", "kind": "model3d", "name", "tags", "summary", "createdAt", "updatedAt", "version": 2, "views": [{"angle", "url"}], "turntable", "glb", "parts": [...]}`
  - `file`：`{"id": "f-…", "kind": "file", "name", "tags", "size", "createdAt", "updatedAt", "download"}`
- `PATCH /api/library/{kind}/{id}`：请求 `{"name"?: "…", "tags"?: ["…"]}`，返回更新后的条目。
- `DELETE /api/library/{kind}/{id}`：返回 `{"ok": true}`。
  - 视频和 3D 图片只是从素材库里移除，任务列表里还在；
  - 文件会真正删除，已经用过它的任务不受影响。
- 进库规则：
  - 视频：完成、有成片的视频任务；
  - 3D 图片：完成、有成品的 3D 任务；
  - 文件：作为参考资料上传过的文件，在建任务时自动进库，按文件名加内容去重。每个用户最多 200 个文件。

## 六、拆解和 3D 打印（2026-10-16 加）

用户的场景：在平台上做一个能拆解的 3D 模型 → 导出文件，用拓竹打印机打印 → 用这个模型做产品介绍或结构讲解视频（套用风格库，直接用模型和拆解数据，不重新建模）。

### 拆解

- 新建 3D 图片时可以打开"做拆解（展示内部结构）"，默认关。打开后：
  - Agent 把内部零件也建出来；
  - 在模型里写拆解数据：`root.userData.sculptRuntime.explode = {"steps": [{"label": "拆下缸盖", "parts": [{"id": "cylinder-head", "offset": [0, 0.35, 0]}]}]}`。
    - 每一步一组零件；`offset` 是零件拆开时的位移，在零件父节点的坐标系里，单位和模型一致；
    - 一个零件只出现在一步里。
- 拆解数据的动画、按风格换画法、零件标注由共用套件 `kit-3d` 实现（`/skills/kit-3d/`），3D 图片的渲染和视频镜头都用它：
  - `explodeAt(model, t)`：t 从 0（组装好）到步数（全部拆开），每一步缓入缓出；
  - `applyLook(model, look, opts)`：`pbr`（原样）、`clay`（素模）、`toon`（卡通着色）、`line`（线稿加平涂，适合机械图解和蓝图风格）；
  - `screenPoints(model, camera, ids)` 和 `callouts(svg, items, opts)`：零件的屏幕位置，以及引线和名称标注。
- 新增的产出：
  - **拆解动图**：组装 → 逐步拆开 → 停留 → 合上，只出 GIF（3D 图片不出视频；成品页的 3D 预览有拆开滑杆）；
  - **拆解图**：拆开状态的 35 度斜侧图，带零件名标注。

### 3D 打印导出（按拓竹 Bambu Studio）

- 导出时用页面把模型的网格取出来，存一份打印源数据：按零件、按颜色分，坐标已经换算到世界坐标。会话里会检查有没有不封闭的网格（零厚度面片、没封口的管子），报给 Agent 修。
- 按需生成：用户在成品页或素材库选机型、高度、出法、颜色数和格式，由 api Lambda 生成文件。
  - 格式：
    - **3MF**（推荐）：标准 3MF，单位毫米，Z 轴朝上，每个零件和颜色一个部件，颜色写成 `basematerials`。Bambu Studio 2.5 以上导入时，可以把颜色对应到 AMS 耗材。
    - **STL**：单色。整体出法是一个文件；零件分开时，每个零件一个文件，打包成 zip。
  - 出法：
    - **整体**：一个物体，零件保持装配位置，多色；
    - **零件分开**：每个零件一个物体，在热床上简单排开，打完拼装。
  - 机型（来自 Bambu Studio 的机型配置）：A1 mini 180×180×180；A1、P1、X1、P2S 256×256×256；H2D 350×320×325；H2S 340×320×340。高度超出机型时报错。
  - 颜色数：1、4、8、16，默认 4，正好一组 AMS。模型的颜色按相近程度归并。
  - 报告：成品尺寸（毫米）、零件数、每种颜色用在哪些零件、警告（没有封闭的网格、缩放后不到 0.8 毫米的细小零件）。

### 接口

- `POST /api/tasks`（3D 图片）多一个 `"explode": true|false`。
- `GET /api/tasks/{id}`（3D 图片）：
  - `request.explode`；
  - `model.asset.explode`：`{"steps": [{"label", "parts": ["零件 id"]}]}` 或 null；
  - `model.versions[].explode`：`{"gif": "<GIF 下载链接>", "image": "<带标注的拆解图>"}` 或 null；
  - `model.versions[].printable`：这个版本有没有打印源数据。
- `POST /api/tasks/{id}/print`：
  - 请求：`{"v": 1, "printer": "a1mini|a1|h2d|h2s", "height": 120, "mode": "whole|parts", "colors": 4, "format": "3mf|stl"}`；
  - 返回：`{"download": "<下载链接>", "file": "文件名", "report": {"sizeMm": [宽, 深, 高], "parts": 12, "objects": 12, "colors": [{"hex": "#2b2b2b", "parts": ["缸体", "…"]}], "warnings": ["…"]}}`。
- 素材库的 3D 条目多两个字段：`explode`（有没有拆解产出）和 `printable`。
- 模型代码接口不变。前端的 3D 预览按 `sculptRuntime.explode` 自己做"拆开 / 合上"的滑杆（算法同 `kit-3d` 的 `explodeAt`）。
