# 管理端第一批：权限、独立服务、模型密钥联动（设计，待审，2026-10-13）

## 0. 这一批做什么

| 做 | 不做（第二批及以后） |
|---|---|
| 一个用户池里区分管理员和普通用户 | Credit 余额、流水、换算比例、月度额度 |

| 操作日志：用户和密钥相关的操作 | |

前端照设计稿（`admin/`）做，第一批用不到的页面先隐藏。

## 1. 权限：一个用户池，两种角色

- **角色怎么区分**：用 Cognito 的用户组，建一个 `admin` 组，组里的人是管理员，其他人都是普通用户。登录后，令牌里的 `cognito:groups` 会带上组名，后端据此判断。
- **第一个管理员（root）**由一键部署脚本创建，例如 `./deploy.sh user add <邮箱> --admin`。它和其他账号一样在用户池里，只是多了 `admin` 组。
- **管理员能做什么**：
  - 开通账号；
  - 停用和启用账号；
  - 重置密码；
  - 把别人设为管理员，或者取消管理员；
  - 管理模型密钥；
  - 查看所有用户的任务和用量。
- **保护规则**：
  - 管理员不能取消自己的管理员身份，也不能停用自己；
  - 系统里至少要保留一个管理员。
- **普通用户**：只能登录用户端，看到的只有自己的任务，和现在一样。
- **管理员也能登录用户端做片**：用同一个账号，在用户端的身份和普通用户一样，看不到别人的任务。
- **管理端的令牌和用户端分开**：
  - 两个前端各用一个应用客户端（app client），管理端的 API 只接受管理端客户端签发的令牌；
  - 管理员在用户端登录拿到的令牌，调不了管理端 API；
  - 管理端 Lambda 还会再检查一遍 `admin` 组，不是管理员一律返回 403。

## 2. 管理端是一个独立服务

```
                    同一个 Cognito 用户池（用户端客户端 / 管理端客户端，admin 组）
                         │                                  │
用户端  CloudFront ─ S3（web/）                   管理端  CloudFront ─ S3（admin/）
         └─ /api/* → API Gateway（用户）              └─ /api/* → API Gateway（管理）
                      └─ Slate-api 等 Lambda                     └─ Slate-admin Lambda（只给它管理所需的权限）
                                   └──────────── 共用：任务表、数据桶、Secrets Manager、Harness ────────────┘
```

- **单独一个 CDK 栈** `<栈名>-admin`，和主栈在同一个 CDK 应用里。它引用主栈的用户池、任务表和密钥，包括：
  - 管理端自己的 S3 和 CloudFront，有独立的访问地址；
  - 一个 API Gateway，挂 Cognito 授权器，只接受管理端客户端的令牌；
  - 一个 `Slate-admin` Lambda，有自己的执行角色。
- **部署**：
  - `./deploy.sh` 依次部署主栈和管理端栈；
  - `./deploy.sh admin` 只更新管理端；
  - `./deploy.sh destroy` 先删管理端栈。
- **管理端 Lambda 的权限**：只给管理所需的部分。
  - 用户池的用户和组管理；
  - 任务表只读，外加写操作日志和配置项；
  - 读写那几个模型密钥；
  - AgentCore Identity 的 API Key 凭证管理。
  - 读不了数据桶里的成片和素材，所以管理员看不到用户的片子。
- **以后可以加**：给管理端加 IP 白名单（WAF）。第一批不做。

## 3. 模型与密钥怎么联动

### 3.1 存在哪里

| 密钥 | 存放位置 | 谁会用到 |
|---|---|---|
| MiniMax 中国区 | Secrets Manager（已有：`<栈名>/minimax-api-key`） | 配音 Lambda。缓存改为 5 分钟过期，换 Key 后几分钟内生效 |
| OpenAI 兼容接口（可以配多个） | AgentCore Identity 的 API Key 凭证。Harness 的 `openAiModelConfig` 只接受这里的凭证 ARN | Harness 调主 Agent 时使用 |
| Bedrock API Key | 同上，存进 AgentCore Identity | 见 3.3，需要先验证 |

- 地址、模型映射、启用开关、优先级顺序这些**非机密配置**，写在任务表的配置项里。
- 页面上 Key 只显示首尾几位，后端任何接口都不返回完整的 Key。
- 这些凭证由管理端在运行时创建，不归 CDK 管。`./deploy.sh destroy --purge` 时，按名称前缀一并删除。

### 3.2 什么时候生效

- 现在每轮任务开始时，turn Lambda 都会给 Harness 指定模型（`model_config`），以后在这里按优先级决定走哪个来源：
  1. OpenAI 兼容接口：已启用，且给"主 Agent"配了模型映射，就用 `openAiModelConfig`，填上模型、凭证 ARN 和地址；
  2. Bedrock API Key：已配置就用它，见 3.3；
  3. 都没有就用 `bedrockModelConfig`，走 Harness 的 IAM 角色，也就是现在的方式。
- 1、2 的先后顺序在管理端可以调换，IAM 角色固定在最后兜底。
- 改了配置不用重新部署，**下一轮任务就生效**。正在跑的那一轮不受影响。
- 被模型安全策略误拦时，照常换下一个备用模型。如果当前来源调用失败，比如 Key 失效，这一轮就退回 IAM 角色重试一次，并在操作日志里记一条。

### 3.3 需要先验证的一点：Bedrock API Key 怎么接进 Harness

Harness 的 Bedrock 模型配置里没有填 API Key 的地方，它固定用执行角色调用。可能的接法有两种，要做个小实验才能确定：

- 用 `liteLlmModelConfig`（模型写成 `bedrock/…`），挂上 Bedrock API Key；
- 用 Bedrock 的 OpenAI 兼容地址，走 `openAiModelConfig`。

如果两种都不行，Bedrock API Key 第一批只用于看图自检这类直接调用。主 Agent 仍然走 IAM 角色，或者走 OpenAI 兼容接口。实验需要临时建一个 IAM 用户来签发 Bedrock API Key，用完删除。

### 3.4 看图自检和配音

- **看图自检**：现在由会话直接用 IAM 角色调 Sonnet。要让它也按优先级走，就照配音的做法加一个代理 Lambda，Key 同样不进沙箱。建议放进第一批，改动不大。
- **配音**：只有 MiniMax 一个来源，失败时退回 Polly，不变。

### 3.5 连通测试

保存前可以先点"测试"，后端用这个 Key 发一个很小的请求：大模型回一句"ok"，MiniMax 合成一个字。结果和耗时显示在卡片上，同时记入操作日志。

## 4. 数据

- **身份、状态和角色**：放在 Cognito，包括邮箱、启用或停用、是否在 `admin` 组。
- **用户的附加信息**：比如部门，放进任务表的新条目 `USER#<sub>`。
- **用量**：第一批从任务表实时统计，按用户、按月算任务数、成片时长和状态分布。等第二批做 Credit 时，再在任务完成时记下每个任务的实际成本。
- **操作日志**：放进任务表的 `AUDIT#<时间>` 条目，保留 3 年，接口只提供读取，不提供删除。

## 5. 管理端 API（第一批）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/me` | 当前管理员 |
| GET | `/users?status=&q=` | 用户列表，带本月任务数、最近活跃时间 |
| POST | `/users` | 开通账号：生成临时密码并发邮件，可选设为管理员 |
| GET | `/users/{sub}` | 用户详情：账号信息、按月用量 |
| GET | `/users/{sub}/tasks` | 这个用户的任务列表：标题、状态、时长、时间 |
| POST | `/users/{sub}/disable`、`/enable`、`/reset-password` | 停用、启用、重置密码 |
| PUT | `/users/{sub}/role` | 设为管理员或取消管理员 |
| GET | `/models` | 模型来源（本账号 IAM 角色）和调用模型的策略名、各用途的模型、MiniMax 密钥的状态（只返回掩码） |
| PUT | `/models/minimax` | 保存或更换 MiniMax Key |
| POST | `/models/test` | MiniMax 连通测试 |

> 2026-10-18 起模型都用 IAM 角色调用，Bedrock API Key、OpenAI 兼容接口和来源优先级的接口都去掉了，见 `docs/model-keys-design.md`。
| GET | `/audit` | 操作日志 |

## 6. 需要你拍板的

1. **管理员能不能再设别人为管理员**：这一稿是"能"，第一个管理员由部署脚本创建。另一种做法是只允许用部署脚本设管理员。
2. **看图自检要不要一起纳入优先级**：这一稿建议放进第一批，见 3.4。
3. **Bedrock API Key 的实验**：会临时建一个 IAM 用户，用完删除，见 3.3。
