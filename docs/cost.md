# 单个任务的 token 和成本（2026-10-12 实测）

## 数据来源

- **模型 token（开缓存前）**：Harness 每轮结束时，`afterInvocation` hook 会把这一轮所有模型调用的输入、输出 token 总数传给 finish Lambda。"每个任务的模型用量和费用"表里的数字是从 finish Lambda 日志里按任务汇总的。当时没开提示缓存，所有输入 token 都按全价计费。
- **模型 token（开缓存后）**：用 `python scripts/task_cost.py [任务 ID]` 统计。Harness 运行时日志里，每次模型调用都有一条 EMF 指标（`strands.event_loop.input/output/cache_read/cache_write`），脚本按会话实例汇总，再按时间对到任务上。下面两处数据**不能**用来算开缓存后的费用：
  - hook 回传的 `inputTokens` 只算没命中缓存的那部分（复利那个任务只有 42）；
  - CloudWatch `AWS/Bedrock` 命名空间下，`global.` 推理配置的 `CacheRead/WriteInputTokenCount` 一直是 0。
- **单价**：取自 AWS Price List API，us-east-1，global 推理配置，单位是每百万 token。

| Opus 4.8 | 被拦时的备用模型 | $5 | $25 | $0.50 |

## 开启提示缓存后（2026-10-12 实测）

开法：Harness 的模型配置和每轮 InvokeHarness 都带上 `additionalParams = {"additionalModelRequestFields": {"cache_control": {"type": "ephemeral"}}}`，只对 Claude 模型生效，GPT 备用模型不带这个字段。

- 最后两行是修复"场景页加载超时"之前跑的：渲染失败了十来次，Agent 一直在重试，所以调用次数和费用都偏高，不代表正常水平。

- **模型费用降了约 75%**：九成以上的输入按缓存读取计费（全价的 1/20）。还要付的主要是缓存写入（全价的 1.25 倍，每段新内容写一次）和输出 token。
- **缓存 5 分钟过期**：两次模型调用之间隔太久（比如一次渲染跑了 5 分钟以上），下一次调用要重新写缓存。片子越长、渲染越慢，命中率会低一些。
- 15～21 秒的片子，正常情况下模型费用 $0.40～0.70。30 秒以上的片子还没有开缓存后的实测，下面"结论"里的数字是按同样的折扣，从开缓存前的实测值推算的。

## 其他费用（实测）

**数据来源**：
- CloudWatch `AWS/Bedrock-AgentCore` 命名空间下的 `CPUUsed-vCPUHours` 和 `MemoryUsed-GBHours` 两个指标，资源分别是 Slate 的 Harness 运行时（`harness_Slate_agent`）和内置浏览器（`aws.browser.v1`），取 5 分钟粒度。
- 分摊方式：按每个任务"创建到最后更新、再加 30 分钟空闲回收期"的时间段分摊；时间段重叠的平分。
- 单价：vCPU 每小时 $0.0895，内存每 GB 每小时 $0.00945（Price List API，us-east-1）。

| 任务 | Harness 会话 | 浏览器渲染 | 看图（Sonnet 5.5） | 配音、搜索、Lambda、S3 等 |
|---|---|---|---|---|
| 五大模型对比（98 秒，8 镜） | $0.05（0.15 vCPU·h，4.0 GB·h） | $0.09（0.70 vCPU·h，3.1 GB·h） | 约 $0.2 | < $0.03 |
| 30 秒看懂 RAG（含修改） | $0.07 | $0.02 | 约 $0.1 | < $0.02 |
| AI 客服助手（30 秒） | $0.06 | $0.01 | 约 $0.1 | < $0.02 |
| 为什么要多喝水（含重试） | $0.10 | $0.01 | 约 $0.1 | < $0.02 |

- **12 小时合计**：Harness 会话 $0.63，其中 CPU 只有 $0.07、**内存 $0.57**；浏览器 $0.28，其中 CPU $0.16、内存 $0.13。
- **会话费用主要是空闲时的内存**。会话 CPU 很低，因为 Agent 大部分时间在等模型返回。但 8 GB 内存从会话启动起一直计费，每轮结束后还要空闲 30 分钟才回收（`idleRuntimeSessionTimeout = 1800`）。把这个值调到 10 分钟，会话费用大约能减半，代价是用户隔很久再修改时，要从 S3 存档恢复工作区，多花十几秒。
- **看图费用**：CloudWatch 显示 Sonnet 5.5 在这段时间共 120 次调用，14 万输入、10 万输出 token，合计约 $1.25，平均每个任务约 $0.1。

## 结论

- **开缓存前**：一支 30 秒左右的片子，总成本约 2.6～4.6 美元。其中模型约 2.5～4.3 美元，AgentCore 会话、浏览器、看图等合计约 0.15～0.25 美元。每次按镜修改约 1 美元；需要大量联网查资料的 90 秒以上片子，约 14 美元。
- **开缓存后**（已上线）：15～21 秒片子实测，模型费用 $0.40～0.70；加上会话、浏览器和看图，总成本约 0.6～0.9 美元。按同样的折扣推算：
  - 30 秒片子：总成本约 0.8～1.3 美元；
  - 每次按镜修改：约 0.3 美元；
  - 98 秒、大量联网查资料的片子：约 4 美元。
- **模型费用仍是大头，但比例降了**：开缓存前占九成以上，开缓存后约七成。剩下的主要是输出 token 和缓存写入。
- **下一个能省的是 Harness 会话的空闲内存**，见上面关于 `idleRuntimeSessionTimeout` 的说明。
- **备用模型更贵**：Opus 4.8 单价更高，而且在这次的样本里用的 token 也更多。拒答兜底只在必要时触发，影响不大。
