# 风格创建（管理端 Skill Creator）：调研和设计（待审）

2026-10-16。需求：在管理端上传一段参考视频，由 Agent 把它做成平台的风格 Skill。生成后先"内测发布"，只有管理员能看到；管理员用它做一两支测试片，确认效果后再"公开发布"，所有用户都能用。

开发期间做过外部调研（skill-creator 逐文件拆解、Bedrock 视频模型、视频分析工具许可、版权）和管理端原型，这份设计在原型基础上落到实现。

## 结论

1. **能做，大部分零件现成**：
   - Harness Agent 加一本新手册：和 3D 图片一样，是一种新的任务类型；
   - `slate-look` 看图、渲染机、渲染自检、内容把关、管理端第一批（用户、权限、操作日志）都已经在线上。
2. **要新做的有四块**：
   - 看视频的工具：切镜头、抽关键帧、拼联系表、算配色和节奏；
   - 生成手册；
   - **不重建镜像就能上线新风格**：现在 44 个风格是打进镜像的；
   - 管理端的风格页面。
3. **skill-creator 借方法，不搬脚本**：
   - 它是 Apache-2.0，可以商用；
   - 但它是给"人和 Claude 在 Claude Code 里一起迭代"设计的：访谈、评审要人，对照测试要子 Agent，触发词优化要 `claude -p`；
   - 我们借它的骨架：写草稿 → 出测试用例 → 试跑 → 逐条打分 → 按意见改 → 下一轮。管理员在管理端的"验证"页上审，代替它的评审页。
4. **Bedrock 上的 Claude 不能直接看视频**：
   - 精确的东西（切点、镜头时长、配色、动作快慢）用 ffmpeg 和 numpy 算出数字；
   - 看得懂的东西（材质、字体气质、构图、招牌手法）让 Claude 看高清关键帧和联系表。
   - 能直接看视频的模型（TwelveLabs Pegasus、Nova）只能给语义描述：Nova 每秒最多看 1 帧，还把画面压成 672×672，动效广告里的小字和快动作都看不清。不作为主路，Pegasus 留作 spike 里的对照项。
5. **最大的不确定是还原度**：从视频里提炼出来的风格，换一个题材做片还像不像。建议先做一次 spike，用两三段参考视频实测，再开工。

## 实测：视频反编译（2026-10-16）

按"截帧看图 → 认元素 → 前后帧推断怎么动 → 写成前端代码框架"的思路做了一次实测。

- **参考视频**：我们自己的一支 34 秒耳机广告（瑞士动态排版风格）。
  - 实测会话里先删掉了这个风格、同类的旧风格，以及风格目录里对它的描述。
  - 事后查过运行日志：Agent 没有读到任何原风格的文件。
- **过程**：
  1. 数值拆帧：切点、动作强度曲线、关键帧、每秒 12 帧的动作条；
  2. 看图认元素；
  3. Agent 自己写了测量脚本，在原分辨率帧上逐帧量位置、大小、颜色和时间；
  4. 挑 3 段写成 `render(t)` 逐帧重建，和原片对比打分，每段改 3～4 轮；
  5. 抽成引擎（20 KB）和中文说明书（15 KB）；
  6. 冷启动试写：另开一次干净的模型调用，只给 Skill、换成讲高铁的科普题材，写一个镜头；
  7. 用这个 Skill 正常做一支完整的片子。
- **结果**：

  | 项目 | 数字 |
  |---|---|
  | 重建三段的轮廓相似度 | 0.86 / 0.78 / 0.81（随手写的粗糙场景只有 0.19） |
  | 动作曲线相关系数 | 0.98 / 0.91 / 0.99 |
  | 配色色差 | 0.1 |
  | 动作峰值时间差（中位） | 0 秒 |
  | 冷启动试写评分（色彩、版式、动作、镜头语法，满分 5） | 5 / 5 / 4 / 4 |
  | 生成用时和花费 | 50 分钟，$9.65（约 12.5 Credit），比估算的低 |
  | 用这个 Skill 做完整片子（线上普通做片任务，题材是高铁的科普） | 39.6 秒，用时 7.7 分钟，1.62 Credit；5 个镜头都调用了生成的引擎 |

- **学到的**：
  1. **数字比看图可靠**：
     - 版式、配色、时长、缓动都是逐帧量出来的；
     - 看图模型会读错小字，还会把静止段说成"轻微抖动"、把柱子说成"有过冲"。实际上全片没有一处过冲；
     - "数字分 4 级上升、每级 0.22 秒"这种手法，只有逐帧测量才看得出来。
     
     所以 `slate-style` 除了拆帧，还要带测量工具：按颜色类别量外接框、追踪元素随时间的位置和大小。
  2. **先重建再抽象**：重建对上了，抽出来的引擎就是准的。引擎准了，以后做片又快又省：这次 7.7 分钟、1.62 Credit，平时一支 25～45 分钟、4～7 Credit。
  3. **一支参考只能反推出它的那一种用法**：
     - 生成的风格比原风格窄：固定钴蓝，页面类型也固定；
     - 原风格允许按题材换信号色，还有"一个不守规矩的元素"、"刀切删除"这些手法。
     
     风格的变化范围要靠多支参考，或者管理员在补充说明里写；生成时还要让 Agent 标出哪些参数可以变。
  4. **自己的成片天然好反编译**：它本来就是代码画出来的，平涂色、没有噪点。真实广告里有实拍、AE 特效、纹理和 3D，会难得多，所以第二轮用真实视频测。

### 第二轮：真实视频（B 站的手绘插画科普）

- **参考视频**：柴知道《实用科普：那些千奇百怪的饮品都是什么？》里讲咖啡类饮品的 73 秒。只用于内部测试，测完删除。
  - 风格：粉彩纯色纸面、手绘平涂的物件和小人、圆角标签、剖面配比图。
  - 频道 logo 和吉祥物没有还原进 Skill，示范镜头用的是新设计的通用角色和物件。
- **流程和第一轮一样**。Agent 又自己写了一组测量工具：
  - 连通块找元素；
  - 分区帧差找动作起止；
  - 模板匹配求位移；
  - 拟合 11 种缓动曲线。
- **结果**：

  | 项目 | 数字 |
  |---|---|
  | 重建三段的动作曲线相关系数 | 0.94 / 0.98 / 0.98，动作峰值时间差 0～0.1 秒（采样间隔就是 0.1 秒） |
  | 轮廓相似度 | 0.47 / 0.63 / 0.51：版式和位置对上了，差在手绘插画的细节 |
  | 配色色差 | 0.6～2.6 |
  | 冷启动试写评分（色彩、版式、动作、镜头语法，满分 5） | 3 / 3 / 3 / 4 |
  | 生成用时和花费 | 51 分钟，$9.54 |
  | 用这个 Skill 做完整片子（题材是切洋葱为什么流泪） | 37 秒，用时 10 分钟，1.74 Credit |

  - 冷启动试写的扣分：第一轮主要是说明书没写清楚，改了说明书再试一轮。动作一项扣分的理由是"参考是淡入"，和逐帧测量不符：参考里的入场是从上方落入。
  - 完整片子里，Agent 照着风格的画法自己新画了一组洋葱道具（`onion-props.js`）。
- **新学到的**：
  1. **时间和缓动在真实视频上照样量得准**：拟合误差最小的是 easeInOutQuad，比第二名小一个数量级。
  2. **难的是"手绘感"**：线条抖动的幅度、填色错位的量没有可靠的数值方法，只能看放大图估计。人物、植物这类插画只能做到"像个意思"。
  3. **看图评审不能评动作**：每 0.5 秒一帧的联系表看不到 0.38 秒的动作。动作要看数值曲线，或者给视觉模型每秒 12 帧以上的动作条。
  4. **生成的配色会超出参考**：参考里只出现了两种纸色，说明书里另外几种是按明度和饱和度外推的，要在风格要素页上标出来，让管理员确认。

## 一、整体流程

```
管理员上传参考视频，填名称、分类、补充说明（不要什么）
  → 生成（一个 Harness 会话，40～90 分钟）
      看视频 → 提炼风格要素 → 写说明书 → 写引擎和示范镜头 → 自检打分（不过关就改，最多 3 轮）
  → 待验证：管理员看对比图、示范镜头、自检结果；不满意就写意见，"按意见重新生成"出下一版
  → 内测发布：只有管理员在用户端的风格库里能看到（带"内测"标）
  → 管理员用它做 1～2 支测试片（正常做片流程）
  → 公开发布：所有用户可见
  → 以后可以下架：风格库里不再出现，已经用过它的老任务照常能改、能重渲
```

状态：生成中 → 待验证 → 内测 → 已公开 → 已下架；也可以在待验证时驳回。

- **公开发布的门槛**：当前版本至少有一支测试片做完（原型里人工清单的最后一项，这里改成系统强制）。
- **改已经公开的风格**：新版本先进内测，公开的仍是旧版本，新版本公开发布后才替换。

## 二、产出要对齐的格式

现在的 43 个影片风格（`film-*`）每个都是：

| 文件 | 内容 |
|---|---|
| `SKILL.md` | 中文引言（先读 film-kit、示范片只学技法）加风格说明。说明的章节固定：本质和不是什么、材质和渲染、色彩、字体和字幕、动作、镜头语法、招牌手法、常见坑。10～15 KB |
| `DEMO.md`、`demo/` | 一支示范短片的说明和源码：画笔引擎、角色绑定、着色器、转场写法 |
| `style.json` | 名称、分类、适用场景、示范片信息 |
| 缩略图 | `web/thumbs/<id>.jpg`，示范片的一帧 |

**只生成影片型**：原型里有"组件型 / 影片型"两种，但组件型风格（编辑图解、瑞士网格这一批）已经下架，现在风格库里都是影片型（外加机械图解），所以先只做影片型。

**说明书写成中文**：现有影片风格的说明是英文原文。新生成的直接写中文，章节和现有的一致，Agent 读起来没有区别。

## 三、生成 Agent 怎么做

新的任务类型 `product: "style"`，跟 3D 图片一样走现有的任务、会话、计费、渲染机流程。新增一本手册 `core-stylegen` 和一个命令 `slate-style`。

### 3.1 看视频（`slate-style probe`）

先算数字，再让模型看图。会话镜像里已经有 ffmpeg、Pillow、numpy，**不用加新依赖**。

| 产出 | 怎么算 |
|---|---|
| 镜头表 | ffmpeg `scdet` 找切点，再按"画面变化量"曲线细分成节拍段：动效片里很多变化发生在同一个画面里，不是传统的切镜头 |
| 节奏 | 镜头时长的平均、中位、最短和最长，每分钟切几次，静止停留多久（可以近似成阅读时间） |
| 配色 | 每个镜头抽几帧，按面积聚类；区分背景色、主色、强调色、文字色，和全片一起合并 |
| 关键帧 | 每段取首、中、尾帧，加上最静止的一帧（排版定格时的完整画面，最适合看字体和版式） |
| 联系表 | 全片 4×4 拼图，带时间码，看构图和节奏 |
| 动作条 | 对入场、转场这类 1～2 秒的动作，按每秒 10 帧拼成一条，让模型描述元素怎么进、错开顺序、怎么出 |
| 字体局部 | 文字区域的原分辨率裁剪，看字体分类、字重、字距 |
| 声音（只记数字） | 有没有旁白、音乐速度、切点是不是卡在节拍上。声音由平台处理，这些只写进说明书当节奏参考，不保存原音乐 |

然后用 `slate-look` 分组看图：先看联系表定整体，再看关键帧定材质和版式，最后看动作条定动作语言。

### 3.2 提炼风格要素（`traits.json`）

管理端"风格要素"页上展示的就是这份：

- 一句话定位；
- 色板，标出每种颜色的角色；
- 材质和画面质感；
- 字体：分类和气质，映射到字体库里最接近的 OFL 字体；
- 签名动作和缓动；
- 镜头语法和转场；
- 节奏数字；
- 不是什么（和现有哪些风格不同）；
- **不能带走的东西**：参考片里的角色、logo、文案、具体画面，生成时显式排除。

### 3.3 写说明书

按第二节的固定章节写。手册里给模板和一个写得好的现有风格做对照。说明书只写抽象规则和数字，不写参考片的具体内容。

### 3.4 写引擎和示范镜头

- `demo/` 写一套引擎：画笔、材质、转场函数；
- 再写 3～4 个示范镜头，每个 6～8 秒，题材换成和参考片无关的通用内容；
- 要求和普通镜头一样：`render(t)` 纯函数、字体来自字体库、不访问外网。

### 3.5 自检和打分（借 skill-creator 的方法）

每一轮出一份打分记录（逐条：检查项、是否通过、依据），格式照 skill-creator 的 `grading.json`：

| 检查 | 怎么做 |
|---|---|
| 能渲染、确定性、没有外部请求、每帧耗时 | 现有的 `slate-render` 和 `slate-qa` |
| 版面 | 现有的出界、重叠、压字幕检查 |
| 还原度 | 参考联系表和示范镜头联系表并排，`slate-look` 按色彩、材质、字体版式、动作、镜头语法、招牌手法六项各打 1～5 分；配色另外算色差 |
| **冷启动试写** | 这是 skill-creator 里"带 Skill 跑一遍"那一步的对应。生成 Agent 自己知道很多没写进说明书的东西，所以另开一次干净的模型调用：只给 SKILL.md 和 DEMO.md，加一个固定的新题材，让它写一个镜头。渲染出来按同样六项打分，分数低说明说明书没写清楚 |
| 没有照搬 | 示范镜头的帧和参考关键帧算感知哈希，太像就拦；再让模型看一遍有没有参考片里的角色、logo、文案 |
| 格式 | frontmatter、大小上限（SKILL.md 不超过 20 KB，整个目录不超过 2 MB）、只引用字体库里的字体 |

不过关就按打分记录改，最多 3 轮，然后交给管理员。

**从 skill-creator 借的**：
- 迭代目录留痕（每轮的产出、打分记录和意见都留着，版本页能看）；
- 打分记录的格式；
- 写说明书的原则：讲清楚为什么、少用"必须"；
- "从意见里归纳通用改法，不针对单个用例打补丁"。

**不借的**：
- 触发词优化：风格是用户点选的，不靠描述触发；
- 打包成 `.skill`；
- 浏览器评审页：用管理端的"验证"页代替；
- 不带 Skill 的对照组：没意义，不带风格肯定不像。

### 3.6 按意见重新生成

管理员在验证页写的意见，作为一轮对话发进生成会话，和视频"按意见修改"是同一套机制，出下一版。

## 四、发布：内测 → 公开（不重建镜像）

### 4.1 存在哪里

- **DynamoDB**：
  - `STYLE#<id>`：名称、分类、状态、内测版本号、公开版本号、来源视频、创建人；
  - `STYLE#<id> / V#<n>`：每版的自检结果、管理员意见、生成任务号、成本。
- **S3**：
  - `styles/<id>/v<n>/`：Skill 文件、`traits.json`、缩略图、示范镜头的小样。同一版发布后不再改。
  - `styles/<id>/source/`：参考视频和抽出的帧，只给管理端看，**不进 Skill 包**。
- **id**：用 `film-<英文短名>`，和内置的 film-* 一样，Agent 照常先读 film-kit。不能和内置风格重名。

### 4.2 怎么进到会话和渲染机

- **建任务时锁定版本**：任务选了生成的风格，服务端把当时的版本号记在任务上，再把 `styles/<id>/v<n>/` 复制进任务的 `input/styles/<id>/`。3D 图片引用已经是这么做的（复制进 `input/models/`）。
  - 风格之后再更新或下架，老任务不受影响，改片和重渲还是原来那一版。
- **会话**：
  - 页面服务把 `/skills/<id>/` 依次去三个地方找：镜像里的风格、已下架的旧风格、任务 `input/styles/`；
  - 任务说明里写明说明书的路径。已下架的旧风格就是这样加载的，已经验证过。
  - 不登记成 Harness 的原生 Skill：用户是直接选风格，不需要靠描述触发。另外实测过按轮挂 S3 上的 Skill，在自定义镜像下只能读到 SKILL.md，读不到同目录的其他文件。
- **渲染机**：场景包现在只打包场景引用到的 `/input/` 文件，要加上引用到的生成风格的目录。
- **内容把关**：
  - 现在受保护的资料（说明书、手册）是部署时打进 Lambda 的；
  - 生成的风格发布时，再写一份规整过的文本索引到 `styles/protected/`；
  - 把关 Lambda 启动时一起加载，每 5 分钟刷新一次。

### 4.3 风格库里谁能看到

- `GET /api/skills` 返回内置目录加已公开的生成风格。调用者在 `admin` 组里时，再加上内测的，带 `beta: true`。
  - 用户端令牌里本来就带 `cognito:groups`，同一个用户池。
- 新建任务时服务端再校验一遍：普通用户选内测风格返回 400。
- 缩略图：生成的风格用 `styles/<id>/v<n>/thumb.jpg` 的签名链接，前端风格库改成"有链接用链接，没有用 thumbs/"。
- 风格和写法互相独立（2026-10-16 起）：新建风格不填适用写法，生成的风格不参与写法的"常搭配"排序。需要的话以后单独做"生成写法"。

### 4.4 以后要不要固化进仓库

公开一段时间、确认稳定的风格，可以用一个脚本拉回 `agent/skills/` 进代码库，跟镜像发布，变成内置风格。可选，不影响上线。

## 五、管理端页面（在原型上改）

| 页面 | 改动 |
|---|---|
| 风格列表 | 状态改成：生成中、待验证、内测、已公开、已下架、已驳回 |
| 新建风格 | 去掉"组件型 / 影片型"和"Skill 规范版本"；保留上传（mp4、mov，不超过 300 MB、5 分钟）、版权确认、名称、id、分类、补充说明、模型、示范镜头数量 |
| 生成中 | 5 步：看视频、提炼要素、写说明书、写引擎和示范镜头、自检打分 |
| 验证 | 参考帧和示范镜头对比、示范小样、自检打分、冷启动试写的结果；按钮改成：按意见重新生成、驳回、**内测发布** |
| 内测中 | 多一块"测试片"：用这个风格做过的任务（管理员自己的），显示状态和用量，链接到用户端看片。按钮：**公开发布**（没有做完的测试片时置灰）、撤回内测 |
| 风格要素、文件、版本 | 和原型一样 |

管理端 Lambda 只多拿 `styles/*` 的读写权限，仍然读不到用户的任务数据。生成任务的产出由事件处理复制到 `styles/` 下。

## 六、版权护栏

依据外部调研（不是法律意见）：风格本身不受版权保护，但具体画面、角色、插画、logo、音乐受保护；整体"概念和感觉"太接近也可能构成实质性相似；字体文件受许可约束。

1. 上传时管理员勾选"有权使用这段视频"，记下来源。
2. Skill 里只放抽象规则和数字，加上新写的引擎和示范镜头。参考片的帧、音频、logo、角色一律不进 Skill 包。
3. 自动检查"没有照搬"（3.5），太像就拦。
4. 风格名用中性描述，不用品牌名或作者名。生成 Agent 也不把来源写进说明书。
5. 字体只用字体库里的 OFL 字体；缺合适的，列出"建议补的字体"给管理员，不自己下载。

## 七、成本和用时（估算，spike 后按实测改）

| 环节 | 估算 |
|---|---|
| 看视频（数值分析加约 40 张图） | $0.5～1 |
| 写说明书、引擎、示范镜头，自检改 1～3 轮（Opus 5.5） | $10～25 |
| 冷启动试写和打分 | $0.5～1 |
| 一次生成合计 | **约 $12～27，16～35 Credit；40～90 分钟** |
| 按意见重新生成一版 | $5～12 |
| 测试片 | 和普通做片一样，一支 2～5 Credit |

原型里写的是从平台账户扣。实现上最省事的做法：记在操作的管理员名下，用量页里标成"风格创建"，管理员可以给自己调额度。

## 八、风险

- **还原度**：最大的风险。动作语言最难从画面里提炼，静态的配色和版式容易。spike 就是测这个。
- **示范片的质量决定风格的质量**：现有影片风格的示范片是精心写的（每个几十到上百 KB 的引擎代码），生成的示范镜头达不到这个水平，用户做出来的片子会偏弱。可以先让示范镜头少而精（3～4 个），把精力放在引擎上。
- **视频里的文字指令**：参考视频画面里的文字会被模型读到。功能只给管理员用，生成会话的权限和普通任务一样（不能直接上网、只能动自己任务的文件），风险可控。
- **生成的代码只在我们的渲染浏览器里跑**：用户只拿到成片。和现在 Agent 写的镜头一样，外部请求本来就被拦截。

## 十一、第一批实现：接口和数据（2026-10-16 开工）

原则：**公开发布以前，生成的风格只有管理员看得到、用得了**。生成任务不进任何人的任务列表和素材库，风格文件只放在平台自己的 `styles/` 前缀下。测试时放进测试账号的风格包已经清理掉了。

### 数据

- **任务表**：`pk = STYLES`，`sk = <风格 id>`，一个风格一条。
  - 基本信息：`name`、`cat`（分类）、`notes`（补充说明）；风格和写法互相独立，不记适用写法；
  - 状态：`status`（draft 待上传 → generating 生成中 → review 待验证 → beta 内测 → public 已公开；以及 retired 已下架、rejected 已驳回、failed 生成失败）；
  - 版本：`betaV`、`publicV`；`versions` 是每版的摘要，最多 10 版；
  - 来源：`source`（参考视频的 key、文件名、大小）、`taskId`（生成任务）、`createdBy`；
  - 测试和意见：`tests`（用这个风格做过的测试任务）、`feedback`（每版的修改意见）。
- **风格 id**：管理员填英文短名，实际 id 是 `film-<短名>`，和内置风格一样，Agent 照常先读 film-kit。不能和内置风格或已有风格重名，创建后不能改。
- **数据桶**：
  - `styles/<id>/source/`：参考视频，只给管理端看；
  - `styles/<id>/v<n>/skill/`：Skill 本身，包括 SKILL.md、DEMO.md、style.json、traits.json、demo/；
  - `styles/<id>/v<n>/review/`：验证材料，包括 recon/R*/side.mp4、cmp.png、scores.json，demo/D*.mp4，trial/*.mp4，report.md，thumb.jpg；
  - `styles/protected/<id>.txt`：内容把关用的文本，内测发布时写入。

### 生成任务

- 新任务类型 `product: "style"`，归在操作的管理员名下，用量记在他的账上。
  - `gsi1pk = STYLEGEN`，所以不出现在任何人的用户端任务列表和素材库里。
  - 用户端接口碰到这种任务一律返回 404。
- 步骤：看视频 `analyze` → 提炼要素 `traits` → 写说明书 `skill` → 写引擎和示范镜头 `engine` → 自检打分 `check`。
- 参考视频复制到任务的 `input/ref/`。Agent 加载新手册 `core-stylegen`，用新命令 `slate-style`：
  - `probe`：拆帧；
  - `frames`：渲染；
  - `compare`：逐帧对比；
  - `trial`：冷启动试写；
  - `export`：检查并发布一版。
- `export` 发布后，事件处理把文件复制到 `styles/<id>/v<n>/`，风格状态变成"待验证"。
- 管理员写的修改意见作为新一轮发进同一个任务，出下一版。

### 做片时怎么用

- 新建任务选了生成的风格：服务端把当时的版本记在任务上，并把 `styles/<id>/v<n>/skill/` 复制进任务的 `input/styles/<id>/`。
- 任务说明里给出说明书的路径。页面里照样用 `/skills/<id>/…` 引用，页面服务会按顺序去找：镜像里的风格、已下架的旧风格、`input/styles/`、生成中的 `style/`。
- 渲染机的场景包会带上用到的生成风格的目录。

### 谁看得到

- `GET /api/skills`：返回内置风格，加上已公开的生成风格。调用者在 admin 组里时，再加上内测中的，带 `beta: true`。
- 每个生成风格条目还有 `thumb`（签名链接）和 `generated: true`。
- 新建任务时服务端再校验一遍：选了看不到的风格返回 400。
- 用内测风格建的任务记进这个风格的 `tests`。

### 管理端接口（都在 /api 下，都记操作日志）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/styles` | 列表：id、名称、分类、状态、内测版和公开版、最新版、缩略图、时间、创建人 |
| POST | `/styles` | 新建。请求：`{name, slug, cat, notes, rights: true, file: {name, size, contentType}}`。返回 `{id, upload: {url, headers}}`，前端用 PUT 把视频传到 url。只收 mp4、mov、webm，不超过 300 MB |
| POST | `/styles/{id}/start` | 视频传完后开始生成，返回 `{taskId}` |
| GET | `/styles/{id}` | 详情：基本信息、来源视频链接；生成任务的状态、步骤、最近的消息、用量；每一版的检查项、分数、风格要素、验证材料链接、文件清单、这一版的修改意见；测试任务列表；每一版能不能公开发布 |
| GET | `/styles/{id}/file?v=&path=` | 看某一版的文本文件，比如 SKILL.md、DEMO.md、demo/engine.js、traits.json、report.md |
| POST | `/styles/{id}/feedback` | `{v, text}`：按意见重新生成 |
| POST | `/styles/{id}/reject` | `{reason}`：驳回 |
| POST | `/styles/{id}/beta` | `{v}`：内测发布 |
| POST | `/styles/{id}/unbeta` | 撤回内测 |
| POST | `/styles/{id}/publish` | `{v}`：公开发布。要求这一版至少有一个做完的测试任务 |
| POST | `/styles/{id}/retire` | 下架：从风格库里去掉，已经用过它的任务照常能改、能重渲 |

`traits.json`（风格要素）的格式：
- `line`：一句话定位；
- `palette`：`[{hex, role}]`；
- `materials`、`motion`、`grammar`、`not`；
- `type`：`[{use, font, weight, size}]`；
- `rhythm`：节奏数字；
- `excluded`：没有带进 Skill 的参考内容；
- `extrapolated`：参考里没有、推断出来的规则，要管理员确认。
