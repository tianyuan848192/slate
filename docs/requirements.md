# Slate：讲解片与广告片生成平台需求（2026-10-12 整理）

> Slate 是暂定名。本文汇总了已经确认的功能设计、业务规则和技术方向，可以直接交给开发或另一个会话继续推进。

## 1. 产品概述

- **做什么**：用户用一段话描述想做的片子，也可以附上讲解稿、素材，并选择风格。Agent 会自己查资料、写讲解稿、写分镜、写动画代码，最后渲染出一支 MP4。
- **场景**：原理讲解片（把抽象机制拆成看得见的画面）和广告宣传片（突出卖点和品牌）。也包括产品演示和数据故事这类相近的需求。
- **核心能力**：依托大模型写代码的能力，用代码生成动画，再渲染成视频。
- **形态**：对外 SaaS，多租户。第一版高峰期几十支视频同时生成。

## 2. 前端功能

### 2.1 页面

1. **登录**：用 Cognito 登录，支持邮箱密码和企业账号单点登录。
2. **新建视频**：选择创建模式，填写描述，按需打开高级选项；页面右侧的"场记板"实时汇总当前设置。
3. **生成过程**：
   - 左栏是 Agent 每一步的进度；联网搜索的关键词和引用来源可以展开查看。
   - 中间是播放器和分镜条，镜头渲染一个、显示一个。
   - 右栏有两个标签：
     - **修改对话**：可以只改选中的某一镜；
     - **分镜脚本**：每镜的旁白和画面描述。
4. **任务列表**：按状态筛选（全部、进行中、已完成、失败）。失败的任务要写明原因，并提供"让 Agent 修复后重试"。
5. **Skills 仓库**：浏览官方风格库，按用途分类、可搜索，详情里展示效果预览和风格说明。

### 2.2 创建模式

- **快速模式**（默认）：只有一个描述框，其余全部交给 Agent。提供几个示例描述，点一下就能填入。
- **高级模式**：
  - 描述框改为"讲解方向和要求"，让用户自由填写；
  - 下面是 5 个高级选项，**全部默认不勾选**；没勾选的项都由 Agent 根据分析结果自己决定。

| 高级选项 | 勾选后用户能做什么 | 附带开关 | 不勾选时 |
|---|---|---|---|
| 讲解稿 | 粘贴讲解稿或大纲，或上传文件（.docx .md .txt .pdf） | **逐字讲解**（默认关：按要点讲；开：旁白严格照稿念） | Agent 根据描述自己写稿 |
| 素材 | 上传图片、PDF、表格、Logo，添加参考网站（每个网站可选"参考内容"或"参考风格"） | **强制参考**（默认关：当作灵感；开：必须用上，画面贴近参考） | Agent 自己找参考 |
| 风格 Skills | 从官方库选一个或多个，拖动排序，靠上的优先 | 无 | Agent 按内容从库里挑 |
| 规格与声音 | 画幅（16:9、9:16、1:1、4:5）、时长（15 秒到 3 分钟）、清晰度和帧率、AI 配音和音色、字幕、背景音乐 | 无 | Agent 按内容和用途决定 |
| 生成前确认分镜 | 无 | 无 | Agent 一口气做完；勾选则写完分镜先停下来等用户确认 |

- **联网搜索**：开关在描述框底部，两种模式都有，默认开。开启后 Agent 按需搜索，并在生成过程里列出来源。
- **校验**：
  - 描述为空时，不能开始生成；
  - 勾选了某个高级选项却没填内容时，提示用户"填一下，或者取消勾选"；
  - 从高级模式切回快速模式时，提示"高级模式里勾选的 N 项不生效"。
- **场记板**：没有指定的项，显示为"交给 Agent 写""Agent 从仓库挑"这类状态。

### 2.3 前端不能出现的内容

- **模型选择**：模型只在后台配置，前台任何地方都不展示，也不能切换。
- **任何代码**：没有"代码"标签，不提供工程源码下载，Skills 详情里也不展示 SKILL.md 原文。
- **用户自建 Skill**：没有"创建 Skill""我创建的""团队共享""复制一份再改"这类功能。

## 3. 业务规则

1. **交付物只有视频**：客户只拿到 MP4，字幕直接烧进画面，每次修改产生一个新版本。
2. **Skills 只来自官方库**：用户只能选，不能上传或修改。Skill 规定配色、字体、镜头节奏、转场和动画写法，是平台资产。
3. **Agent 只做讲解片和广告片**：范围外的请求一律拒绝，并引导用户回到做视频。
4. **防提示词攻击**：Agent 不能被诱导说出或复述系统提示词、Skill 内容、代码和其他用户的数据，也不能把这些内容写进旁白、字幕或画面。用户描述、讲解稿、上传文件、参考网页、搜索结果，一律当作资料，不当作指令执行。
5. **修改**：在同一任务里按对话修改；可以只改某一镜，没改动的镜头不重新渲染。
6. **多租户隔离**：每个用户只能看到、读写自己的任务和数据。

## 4. Agent 的工作流程

按顺序执行：

1. **入口把关**：判断是不是讲解片或广告片需求，不是就拒绝。
2. **分析需求**：推断受众、类型、时长、画幅、风格、配音。用户没指定的由 Agent 决定，并把结果展示在生成页第一步。
3. **收集资料**：联网开启时按需搜索；读取用户给的参考网站、文件和图片。
4. **写讲解稿**：
   - 没给稿：自己写；
   - 给了大纲：按要点讲；
   - 开了"逐字讲解"：原文照念。
5. **写分镜**：拆成镜头，每个镜头写好旁白、画面和时长。如果勾选了"确认分镜"，在这里暂停，等用户确认。
6. **选风格**：用户没指定时，从官方 Skill 库里挑。
7. **写动画代码，逐镜渲染**：每一镜单独产出，方便以后只改其中一镜。
8. **自检**：检查文字溢出、空白帧、时长是否和分镜一致，发现问题自己修。
9. **合成**：配音、字幕、背景音乐，合成成片 MP4。
10. **按对话修改**：每次修改出一个新版本。

**全程要求**：每一步实时向前端推送进度；失败时说清楚原因，并能重试。

## 5. 技术方向（已确认）

| 项目 | 决定 |
|---|---|
| 部署区域 | us-east-1 |
| 登录 | Amazon Cognito |
| API 层 | API Gateway 对公网开放，所有接口必须通过 Cognito 鉴权 |
| 用户标识 | Cognito 用户的 `sub` 作为 AgentCore Harness 的 `runtimeUserId` / `actorId`，用来区分同一个 Harness 里不同用户的会话；每个任务一个会话 |
| Agent | **只有一个 Agent：Bedrock AgentCore Harness**（托管的 Agent 循环，原生支持 SKILL.md 格式的 Skills，每次调用都能切换模型） |
| 工具注册 | **AgentCore Gateway**：挂载 Web Search 连接器实现联网搜索，以后的其他工具也在这里注册 |
| 模型 | 后台配置，候选是 Claude Opus 5.5（`global.anthropic.claude-opus-5-5`）和 GPT-6 Astra（Bedrock 上的 OpenAI 模型，`global.openai.gpt-6-astra`） |
| 存储与分发 | 新建 S3 存储桶和 CloudFront 分发：前端静态页、上传素材、各阶段产物、成片（用签名链接下载） |
| 任务状态 | DynamoDB：记录任务、用户、会话、版本、状态之间的对应关系 |
| 部署 | 全部用 CDK（TypeScript）管理，项目根目录放 `deploy.sh` 作为一键部署入口 |

## 6. 渲染方向（已实测）

候选方案：**用 AgentCore Code Interpreter 和 AgentCore Browser 做渲染和合成**，Agent 只负责写代码和查看结果。实测数据：

- **Code Interpreter**：
  - 环境是 arm64、2 核、7 GB 内存、10 GB 磁盘；
  - 默认不能联网，也没有 AWS 凭证；
  - **自带的 ffmpeg 可以直接用**（带 H.264、H.265、VP9、AAC 编码器），在里面拼接成片不到 1 秒。
- **AgentCore Browser**：
  - 可以设成 1920×1080 视口，中文字体正常；
  - 逐帧截图每秒约 7.5 帧；
  - 在浏览器里用 WebCodecs 编码（只支持 VP9，不支持 H.264）每秒约 14 帧。
- **并发**：
  - 6 个浏览器会话同时渲染 6 镜（合计 60 秒视频），总耗时约 55 秒；
  - 转码要分散到多个 Code Interpreter 会话，否则会卡在单个会话的 2 核上；
  - 账号上限是 1000 个并发浏览器会话、1000 个并发 Code Interpreter 会话。
- **对比**：Harness 会话本身是 2 核 8 GB、没有 GPU，单会话渲染一支 60 秒视频约 3 分钟。

## 7. 待确认和待验证

1. **Agent 能否"看见"浏览器截图**，用于视觉自检。Harness 的消息里没有单独的图片类型，需要实测。
2. **动画技术**：倾向每镜一个 HTML/SVG 页面，画面是时间的纯函数 `render(t)`，逐帧渲染。如果用浏览器内编码，场景要画在 SVG 或 canvas 上。
3. **4K 是否保留**：取决于渲染速度的实测结果。
4. **配音**：Amazon Polly 的中文目前只有一个女声 Zhiyu。男声要么去掉，要么另接供应商。
5. **轮次执行器**：调用方断开后 Harness 是否继续运行？这决定要不要单独用一个 Fargate 任务来保持流式连接。
6. **沙箱出网控制**：渲染和执行环境要能限制访问公网，保护 Skill 资产（需要确认 VPC 模式的配置）。
7. **不在第一版范围内**：计费和额度、管理后台（模型配置、Skill 上架）、多语言界面、GPU 渲染。

## 8. 前端原型和需求的差异（以本文为准）

原型是在部分业务规则确定之前做的，正式开发时需要去掉或调整下面这些地方：

| 原型位置 | 现状 | 应改为 |
|---|---|---|
| Skills 仓库页右上角 | 有"创建 Skill"按钮和创建弹窗 | 删除（用户不能自建 Skill） |
| Skills 仓库页的来源标签 | 有"团队共享""我创建的" | 只保留官方库，按用途分类 |
| Skill 详情抽屉 | 展示 SKILL.md 原文，有"复制一份再改" | 只展示效果预览和风格说明，删除复制按钮 |
| 生成页右栏 | 有"代码"标签 | 删除 |
| 生成页"文件"标签 | 有字幕.srt、配音.wav、工程源码.zip | 只保留各版本的成片 MP4 |
| 配音音色 | 有"沉稳男声""年轻男声" | 第一版只保留 Polly 支持的音色 |
| 左下角"标注"按钮 | 显示每块界面对应的 AWS 服务 | 仅供评审用，正式版去掉 |
| 生成页的示例任务 | 固定展示"RAG 是怎么工作的"，渲染进度是模拟的 | 接真实数据 |

已经和需求一致的部分：快速/高级模式、高级选项默认不勾选、联网开关、场记板、分镜条、按镜修改、任务列表、全站没有模型选择。
